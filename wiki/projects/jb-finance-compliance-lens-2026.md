# JB금융 Fin:AI Challenge 2026 — 컴플라이언스렌즈

## 1. 개요

- **코드 저장소**: https://github.com/accidentable/my-hack — 로컬 폴더에는 제안서만 있고 코드는 저장소에만 있음 (출처: 로컬 git 원격, 2026-09-22 확인)

- 대회명: JB금융그룹 Fin:AI Challenge
- 주제: 지정주제 2 — 준법자문가 AI Agent 서비스 개발
- 팀명: 쌀과자 / 팀원: 윤태호
- 서비스명: 컴플라이언스렌즈 (ComplianceLens)
- 산출물: 예선 MVP 제안서 (원본 PDF `컴플라이언스렌즈_MVP 제안서.pdf`)
- 한 줄 소개: 멀티모달·다국어 금융 콘텐츠를 게시 전에 자동으로 1차 사전심의하는 AI Agent
- 기간: 자료에 없음 (인용된 기사가 2026-03 ~ 2026-05이므로 그 이후 진행 (추정))
- 결과(수상 여부): 자료에 없음

## 2. 문제 정의

증권사 서포터즈로 콘텐츠를 직접 만들며 겪은 준법 사전심의의 구조적 병목 세 가지에서 출발한다.

1. **속도** — 심의 병목이 트렌드를 놓치게 한다. 콘텐츠는 속도가 점점 더 중요해지는데 사람이 그 속도를 따라잡지 못한다.
2. **객관성·맥락** — "나만 괜찮은 것"은 통과 기준이 아니다. 1인의 감각에 의존한 판단은 기준이 될 수 없다.
3. **외국어** — 1인 심의로는 단어도 맥락도 벅차다.

근거로 든 사례 둘.

- **스타벅스 사례**: 검수 부재가 아니라 속도의 문제였다. 연간 프로모션 222건(이틀에 1건꼴), 지난달 동시 진행 16건으로 프로모션 물량이 내부 검수 속도를 추월했다. 출처: 비즈한국, 「'탱크데이' 사건의 진짜 원인」, 2026.05.19.
- **JB금융의 외국인 대출**: 외국인 대출 1조 규모로 외국인 고객이 핵심 영업이고 외국어 홍보 콘텐츠 비중이 높아 외국어 심의가 영업의 전제 조건인데, 담당자가 언어를 못 읽어 외부 번역을 거치며 수일~수주 지연되고 그 사이 미심의·불완전판매 리스크가 쌓인다. 언어·채널이 늘수록 같은 인력이 같은 방식으로 처리해 심의 리소스가 선형으로 증가하는 구조다. 출처: 머니투데이 등, 2026.03 (2026년 2월 말 기준).

기대효과 절에서는 문제를 한 문장으로 다시 정리한다. AI로 콘텐츠 **생성**이 빨라진 시대에 병목은 **검수**로 옮겨갔다는 것. 페리카나 AI 광고 논란(2026.5)처럼 AI로 빠르게 만든 콘텐츠가 표현·정서를 놓쳐 사과·삭제로 이어진 사례를 들며, 최종 책임은 기업에 남으므로 사전 검수가 더 중요해졌다고 본다.

## 3. 접근

### 3-1. 6단계 파이프라인

콘텐츠를 업로드하면 AI Agent가 여섯 단계를 자동 수행하고, 사람은 마지막에 검토·승인만 한다.

| 단계 | 이름 | 하는 일 |
|---|---|---|
| ① | 수집 (Ingest) | 멀티모달 콘텐츠 인식. 이미지·자막에서 검사 대상 '주장'을 추출하고 원문 + 한국어 병기 |
| ② | 검색 (Retrieve) | 규제 근거 검색(RAG). 주장별로 적용 규정 청크를 의미검색으로 매핑 |
| ③ | 판단 (Assess) | 규칙 + LLM 하이브리드 판정. 위반 목록을 근거·심각도·신뢰도와 함께 도출 |
| ④ | 검증 (Verify) | 근거 검증·자기수정. 인용 조항 실재 여부를 대조해 가짜면 폐기 후 재판정(≤2회) |
| ⑤ | 생성 (Generate) | 심의의견서 생성. 위반·근거·현재표현·수정안을 담은 결재용 의견서 자동 작성 |
| ⑥ | 검토 (HITL) | 준법관리자가 승인/반려/코멘트를 반영해 최종 의견서 재생성 |

산출물은 심의의견서이고 PDF로 출력해 공유한다. 의견서 구성 요소는 위반 항목, 근거 규정(조항), 현재 표현, 수정안, 심각도·신뢰도이며 중복 인용은 dedup 후 출력한다.

데모 예시로 든 GPT 생성 홍보 포스터에서는 "연 8.0% 최고 금리", "누구나 무조건 가입 가능", "이번 주 마감! 지금 신청하세요" 세 주장을 추출하고, 금소법 제21조(부당권유금지)·제22조(예금성상품 광고)로 매핑한 뒤 다음처럼 판정한다.

- HIGH — "무조건 가입" → 부당권유 (금소법 제21조) · 신뢰도 100%
- HIGH — 중요사항 누락 → 설명의무 위반 (제19조) · 신뢰도 95%
- MED — 우대금리만 강조(우대조건 미명시) · 신뢰도 88%

### 3-2. 네 가지 핵심 기술 결정

"준법심의는 책임이 따르는 결정"이므로 자율 LLM 대신 통제 가능성을 우선했다는 것이 설계 원칙이다.

1. **그래프 고정 (LangGraph)** — 다음 행동을 LLM이 정하면 책임 추적·재현이 불가하다. 고정 그래프로 재현·단계별 검증·정지/재개를 가능하게 했다. → [[fixed-graph-hitl-agent]]
2. **규칙엔진 + LLM 하이브리드** — 필수고지 누락 같은 결정 사항을 확률적 LLM에 맡길 수 없다. 누락 0% 놓침 보장, 이중 적발 자동 병합. → [[rule-engine-llm-split]]
3. **인덱스 그라운딩 검증** — 컨텍스트 밖 가짜 조항을 지어내는 환각 차단. '구조 환각' 100% 차단, 내용 환각은 규칙·HITL로 보강. → [[citation-grounding-verification]]
4. **HITL INTERRUPT** — 책임은 사람에게 남아야 한다(법적 책임·도입 거부감). "책임은 사람, 속도는 AI"를 코드로 강제. → [[fixed-graph-hitl-agent]]

챗봇이 아니라 Agent인 이유로 든 차별점도 같은 네 가지에 대응한다. 여기에 **원문 직접 심의**가 더해진다. 번역본이 아니라 원문(베트남어 등) 기준으로 판정해 번역 과정의 의미 손실 없이 외국어를 심의한다. recall이 생명인 컴플라이언스 특성을 반영해 규칙엔진으로 결정론적 포착을 보장하고, 과장·오해 표현의 뉘앙스만 LLM에 맡긴다.

### 3-3. 데이터와 스택

- 데이터: 금소법 광고규제 핵심 6건 — 대출성, 예금성, 설명의무, 부당권유, 광고일반, 협회투자. 출처는 국가법령정보센터. 여기에 베트남어·한국어 데모 카드.
- 스택
  - LangGraph 1.0 (오케스트레이션)
  - gpt-5.4 판정 + gpt-5.4-mini 비전
  - Chroma + text-embedding-3-small
  - FastAPI·SSE / Next.js·Tailwind
  - Structured Outputs (Pydantic 강제)

### 3-4. 사용자 시나리오

**① 마케팅 담당자·외주 제작사** — SNS·카드뉴스·릴스·홍보 포스터를 만들어 게시 전 준법심의를 받아야 하는 사람. 이전에는 심의 통과까지 한 달+ 대기, 반려 이유도 명확하지 않은 채 재작업, 외국어 콘텐츠는 더 막막했다. 도입 후에는 올리면 1분 이내로 어디가·왜 문제인지와 수정안까지 나오고, 규정을 몰라도 고치는 법을 안내받고, 통과될 콘텐츠를 처음부터 만들어 재작업·대기가 격감하며, 외국어 콘텐츠도 한국어로 문제를 확인한다.

**② 콘텐츠 준법관리자** — 모든 대고객 콘텐츠의 위반 여부를 최종 판단하고 책임지는 사람. 이전에는 전 콘텐츠 전수 수작업 심의, 외국어는 직접 못 읽음, 물량·휴먼에러·책임 부담이 문제였다. 도입 후에는 AI가 1차로 근거까지 정리해 사람은 검토·승인만 하고, 명백한 위반이 걸러진 뒤 근거·심각도와 함께 검토하며, 외국어도 한국어 판정으로 즉시 확인한다. 최종 결정·책임은 그대로 사람에게 남는다(HITL).

## 4. 잘된 점 / 안된 점

원자료가 예선 제안서라 회고나 실패 기록이 없다. 자료에서 읽히는 것은 강점 주장과 스스로 인정한 한계뿐이다.

- 강점으로 내세운 것: 원문 직접 심의, 규칙+LLM 하이브리드, 근거 검증·자기수정, HITL 정지.
- 스스로 인정한 한계: 인덱스 그라운딩 검증은 '구조 환각'(존재하지 않는 조항 번호 인용)만 100% 차단하고, 조항은 실재하지만 해석이 틀린 '내용 환각'은 규칙엔진과 HITL로 보강한다고만 서술한다.
- 데이터 범위 한계: 규정 데이터가 금소법 광고규제 핵심 6건, 데모 언어가 베트남어·한국어로 한정된 MVP 범위다.
- 심의 리드타임 "주~월"에서 "분 단위"로 단축, "1분 이내" 같은 수치는 제안서의 기대효과 서술이며 실측 결과인지는 자료에 없음.

## 5. 재사용 가능한 것

원자료는 제안서 PDF 한 건이라 코드 경로나 저장소 구조가 없다. 재사용 가능한 것은 설계 패턴이다.

- 6단계 파이프라인 구조(수집 → 검색 → 판단 → 검증 → 생성 → HITL). 규제·심사·검수가 걸린 도메인에 그대로 옮길 수 있는 뼈대.
- 판정 출력 스키마: 위반 항목 / 근거 규정(조항) / 현재 표현 / 수정안 / 심각도(HIGH·MED) / 신뢰도(%). Structured Outputs로 Pydantic 강제.
- 자기수정 루프 설계: 인용 조항을 reg_index와 대조해 실재하지 않으면 폐기 후 재판정, 재시도 상한 2회.
- 원문 우선 심의 원칙: 다국어 콘텐츠를 번역본이 아니라 원문 기준으로 판정하고 결과만 한국어로 병기.
- 원자료 자체(`raw/done/jb-finance-2026-compliance-lens-mvp.md`)가 문제 정의 → 솔루션 → 기능 → 기술 결정 → 유즈케이스 → 기대효과 순서의 제안서 목차 템플릿으로 쓸 수 있다.

## 6. 향후 확장

- 최종 심의서를 .md로 만든 뒤 AI 이미지 생성 모델로 검수 내용을 반영한 콘텐츠를 **재생성**하는 단계까지 확장.
- 페리카나·스타벅스 사례처럼 한국 마케팅은 맥락이 매우 중요하므로, 맥락까지 이해하는 AI Agent를 만드는 것이 목표.
- 검수 병목을 분 단위로 줄여 생성·승인·배포를 잇는 'AI 네이티브 파이프라인'으로 만드는 것이 기대효과의 최종 그림.
