# JB금융 Fin:AI Challenge 2026 — 컴플라이언스렌즈

## 1. 개요

- **코드 저장소**: https://github.com/accidentable/my-hack — 로컬 폴더에는 제안서만 있고 코드는 저장소에만 있음 (출처: 로컬 git 원격, 2026-09-22 확인)

- 대회명: JB금융그룹 Fin:AI Challenge
- 주제: 지정주제 2 — 준법자문가 AI Agent 서비스 개발
- 팀명: 쌀과자 / 팀원: 1인
- 서비스명: 컴플라이언스렌즈 (ComplianceLens)
- 산출물: 예선 MVP 제안서 (원본 PDF `컴플라이언스렌즈_MVP 제안서.pdf`)
- 한 줄 소개: 멀티모달·다국어 금융 콘텐츠를 게시 전에 자동으로 1차 사전심의하는 AI Agent
- 기간: 자료에 없음 (인용된 기사가 2026-03 ~ 2026-05이므로 그 이후 진행 (추정))
- 결과(수상 여부): 자료에 없음

## 2. 문제 정의

증권사 서포터즈로 콘텐츠를 직접 만들며 겪은 준법 사전심의의 구조적 병목 세 가지에서 출발한다.

1. **속도** — 심의 병목이 트렌드를 놓치게 한다. 콘텐츠는 속도가 점점 더 중요해지는데 사람이 그 속도를 따라잡지 못한다.
2. **객관성·맥락** — "나만 괜찮은 것"은 통과 기준이 아니다. 1인의 감각에 의존한 판단은 기준이 될 수 없다.
3. **외국어** — 1인 심의로는 단어도 맥락도 벅차다.

근거로 든 사례 둘.

- **스타벅스 사례**: 검수 부재가 아니라 속도의 문제였다. 연간 프로모션 222건(이틀에 1건꼴), 지난달 동시 진행 16건으로 프로모션 물량이 내부 검수 속도를 추월했다. 출처: 비즈한국, 「'탱크데이' 사건의 진짜 원인」, 2026.05.19.
- **JB금융의 외국인 대출**: 외국인 대출 1조 규모로 외국인 고객이 핵심 영업이고 외국어 홍보 콘텐츠 비중이 높아 외국어 심의가 영업의 전제 조건인데, 담당자가 언어를 못 읽어 외부 번역을 거치며 수일~수주 지연되고 그 사이 미심의·불완전판매 리스크가 쌓인다. 언어·채널이 늘수록 같은 인력이 같은 방식으로 처리해 심의 리소스가 선형으로 증가하는 구조다. 출처: 머니투데이 등, 2026.03 (2026년 2월 말 기준).

기대효과 절에서는 문제를 한 문장으로 다시 정리한다. AI로 콘텐츠 **생성**이 빨라진 시대에 병목은 **검수**로 옮겨갔다는 것. 페리카나 AI 광고 논란(2026.5)처럼 AI로 빠르게 만든 콘텐츠가 표현·정서를 놓쳐 사과·삭제로 이어진 사례를 들며, 최종 책임은 기업에 남으므로 사전 검수가 더 중요해졌다고 본다.

## 3. 접근

### 3-1. 6단계 파이프라인

콘텐츠를 업로드하면 AI Agent가 여섯 단계를 자동 수행하고, 사람은 마지막에 검토·승인만 한다.

| 단계 | 이름 | 하는 일 |
|---|---|---|
| ① | 수집 (Ingest) | 멀티모달 콘텐츠 인식. 이미지·자막에서 검사 대상 '주장'을 추출하고 원문 + 한국어 병기 |
| ② | 검색 (Retrieve) | 규제 근거 검색(RAG). 주장별로 적용 규정 청크를 의미검색으로 매핑 |
| ③ | 판단 (Assess) | 규칙 + LLM 하이브리드 판정. 위반 목록을 근거·심각도·신뢰도와 함께 도출 |
| ④ | 검증 (Verify) | 근거 검증·자기수정. 인용 조항 실재 여부를 대조해 가짜면 폐기 후 재판정(≤2회) |
| ⑤ | 생성 (Generate) | 심의의견서 생성. 위반·근거·현재표현·수정안을 담은 결재용 의견서 자동 작성 |
| ⑥ | 검토 (HITL) | 준법관리자가 승인/반려/코멘트를 반영해 최종 의견서 재생성 |

산출물은 심의의견서이고 PDF로 출력해 공유한다. 의견서 구성 요소는 위반 항목, 근거 규정(조항), 현재 표현, 수정안, 심각도·신뢰도이며 중복 인용은 dedup 후 출력한다.

데모 예시로 든 GPT 생성 홍보 포스터에서는 "연 8.0% 최고 금리", "누구나 무조건 가입 가능", "이번 주 마감! 지금 신청하세요" 세 주장을 추출하고, 금소법 제21조(부당권유금지)·제22조(예금성상품 광고)로 매핑한 뒤 다음처럼 판정한다.

- HIGH — "무조건 가입" → 부당권유 (금소법 제21조) · 신뢰도 100%
- HIGH — 중요사항 누락 → 설명의무 위반 (제19조) · 신뢰도 95%
- MED — 우대금리만 강조(우대조건 미명시) · 신뢰도 88%

### 3-2. 네 가지 핵심 기술 결정

"준법심의는 책임이 따르는 결정"이므로 자율 LLM 대신 통제 가능성을 우선했다는 것이 설계 원칙이다.

1. **그래프 고정 (LangGraph)** — 다음 행동을 LLM이 정하면 책임 추적·재현이 불가하다. 고정 그래프로 재현·단계별 검증·정지/재개를 가능하게 했다. → [[fixed-graph-hitl-agent]]
2. **규칙엔진 + LLM 하이브리드** — 필수고지 누락 같은 결정 사항을 확률적 LLM에 맡길 수 없다. 누락 0% 놓침 보장, 이중 적발 자동 병합. → [[rule-engine-llm-split]]
3. **인덱스 그라운딩 검증** — 컨텍스트 밖 가짜 조항을 지어내는 환각 차단. '구조 환각' 100% 차단, 내용 환각은 규칙·HITL로 보강. → [[citation-grounding-verification]]
4. **HITL INTERRUPT** — 책임은 사람에게 남아야 한다(법적 책임·도입 거부감). "책임은 사람, 속도는 AI"를 코드로 강제. → [[fixed-graph-hitl-agent]]

챗봇이 아니라 Agent인 이유로 든 차별점도 같은 네 가지에 대응한다. 여기에 **원문 직접 심의**가 더해진다. 번역본이 아니라 원문(베트남어 등) 기준으로 판정해 번역 과정의 의미 손실 없이 외국어를 심의한다. recall이 생명인 컴플라이언스 특성을 반영해 규칙엔진으로 결정론적 포착을 보장하고, 과장·오해 표현의 뉘앙스만 LLM에 맡긴다.

### 3-3. 데이터와 스택

- 데이터: 금소법 광고규제 핵심 6건 — 대출성, 예금성, 설명의무, 부당권유, 광고일반, 협회투자. 출처는 국가법령정보센터. 여기에 베트남어·한국어 데모 카드.
- 스택
  - LangGraph 1.0 (오케스트레이션)
  - gpt-5.4 판정 + gpt-5.4-mini 비전
  - Chroma + text-embedding-3-small
  - FastAPI·SSE / Next.js·Tailwind
  - Structured Outputs (Pydantic 강제)

### 3-4. 사용자 시나리오

**① 마케팅 담당자·외주 제작사** — SNS·카드뉴스·릴스·홍보 포스터를 만들어 게시 전 준법심의를 받아야 하는 사람. 이전에는 심의 통과까지 한 달+ 대기, 반려 이유도 명확하지 않은 채 재작업, 외국어 콘텐츠는 더 막막했다. 도입 후에는 올리면 1분 이내로 어디가·왜 문제인지와 수정안까지 나오고, 규정을 몰라도 고치는 법을 안내받고, 통과될 콘텐츠를 처음부터 만들어 재작업·대기가 격감하며, 외국어 콘텐츠도 한국어로 문제를 확인한다.

**② 콘텐츠 준법관리자** — 모든 대고객 콘텐츠의 위반 여부를 최종 판단하고 책임지는 사람. 이전에는 전 콘텐츠 전수 수작업 심의, 외국어는 직접 못 읽음, 물량·휴먼에러·책임 부담이 문제였다. 도입 후에는 AI가 1차로 근거까지 정리해 사람은 검토·승인만 하고, 명백한 위반이 걸러진 뒤 근거·심각도와 함께 검토하며, 외국어도 한국어 판정으로 즉시 확인한다. 최종 결정·책임은 그대로 사람에게 남는다(HITL).

## 4. 잘된 점 / 안된 점

원자료가 예선 제안서라 회고나 실패 기록이 없다. 자료에서 읽히는 것은 강점 주장과 스스로 인정한 한계뿐이다.

- 강점으로 내세운 것: 원문 직접 심의, 규칙+LLM 하이브리드, 근거 검증·자기수정, HITL 정지.
- 스스로 인정한 한계: 인덱스 그라운딩 검증은 '구조 환각'(존재하지 않는 조항 번호 인용)만 100% 차단하고, 조항은 실재하지만 해석이 틀린 '내용 환각'은 규칙엔진과 HITL로 보강한다고만 서술한다.
- 데이터 범위 한계: 규정 데이터가 금소법 광고규제 핵심 6건, 데모 언어가 베트남어·한국어로 한정된 MVP 범위다.
- 심의 리드타임 "주~월"에서 "분 단위"로 단축, "1분 이내" 같은 수치는 제안서의 기대효과 서술이며 실측 결과인지는 자료에 없음.

## 5. 재사용 가능한 것

원자료는 제안서 PDF 한 건이라 코드 경로나 저장소 구조가 없다. 재사용 가능한 것은 설계 패턴이다.

- 6단계 파이프라인 구조(수집 → 검색 → 판단 → 검증 → 생성 → HITL). 규제·심사·검수가 걸린 도메인에 그대로 옮길 수 있는 뼈대.
- 판정 출력 스키마: 위반 항목 / 근거 규정(조항) / 현재 표현 / 수정안 / 심각도(HIGH·MED) / 신뢰도(%). Structured Outputs로 Pydantic 강제.
- 자기수정 루프 설계: 인용 조항을 reg_index와 대조해 실재하지 않으면 폐기 후 재판정, 재시도 상한 2회.
- 원문 우선 심의 원칙: 다국어 콘텐츠를 번역본이 아니라 원문 기준으로 판정하고 결과만 한국어로 병기.
- 원자료 자체(`raw/done/jb-finance-2026-compliance-lens-mvp.md`)가 문제 정의 → 솔루션 → 기능 → 기술 결정 → 유즈케이스 → 기대효과 순서의 제안서 목차 템플릿으로 쓸 수 있다.

## 6. 향후 확장

- 최종 심의서를 .md로 만든 뒤 AI 이미지 생성 모델로 검수 내용을 반영한 콘텐츠를 **재생성**하는 단계까지 확장.
- 페리카나·스타벅스 사례처럼 한국 마케팅은 맥락이 매우 중요하므로, 맥락까지 이해하는 AI Agent를 만드는 것이 목표.
- 검수 병목을 분 단위로 줄여 생성·승인·배포를 잇는 'AI 네이티브 파이프라인'으로 만드는 것이 기대효과의 최종 그림.

### 한 문장 소개

금융 콘텐츠를 게시 전에 준법 사전심의하는 일이 1인 수작업이라 외국어 콘텐츠는 외부 번역까지 거쳐 수일에서 수주가 걸립니다. 멀티모달·다국어 콘텐츠를 올리면 수집, 검색, 판단, 검증, 생성, 사람 검토 여섯 단계를 자동으로 수행해 결재용 심의의견서를 내고 사람은 승인만 하는 AI Agent를 제안했고, 예선 MVP 제안서 단계라 결과는 자료에 없습니다.

| gpt-5.4 판정 + gpt-5.4-mini 비전 | ③판단 / ①수집(이미지·자막에서 주장 추출) | 이유 자료에 없음 (비전에 더 작은 모델을 배치한 근거가 제안서에 없습니다) | 이유 자료에 없음 |
| Structured Outputs (Pydantic 강제) | 판정 출력 스키마 고정 | 이유 자료에 없음. 다만 출력 항목이 위반 항목·근거 규정·현재 표현·수정안·심각도·신뢰도로 고정되어야 의견서 자동 작성과 ④검증의 조항 대조가 가능합니다 (추정) | 이유 자료에 없음 |
| reg_index 대조 (인덱스 그라운딩 검증) | ④검증. 인용 조항 실재 확인, 가짜면 폐기 후 재판정(≤2회) | 컨텍스트 밖 가짜 조항을 지어내는 환각이 컴플라이언스에서는 치명적이라 넣었습니다 → [[citation-grounding-verification]] | 구조 환각만 100% 차단하고 내용 환각(조항은 실재하나 해석이 틀림)은 규칙과 HITL로 보강하는 데 그쳤습니다 |
| FastAPI·SSE / Next.js·Tailwind | 백엔드·스트리밍 / 프론트 | 이유 자료에 없음 | 이유 자료에 없음 |

### 고민한 점

- **자율 에이전트로 갈 것인가 그래프를 고정할 것인가** — 준법심의는 책임이 따르는 결정이라 다음 행동을 모델이 고르게 두면 나중에 왜 그렇게 판정했는지 되짚을 수가 없다고 봤습니다. 그래서 유연성을 포기하고 그래프를 고정하는 쪽으로 갔고, 나머지 결정 세 가지(규칙+LLM 하이브리드, 인덱스 그라운딩 검증, HITL INTERRUPT)도 같은 방향으로 맞췄습니다. 챗봇이 아니라 Agent라고 부른 근거도 같은 네 가지입니다.
- **외국어 콘텐츠를 번역해서 심의할 것인가 원문으로 심의할 것인가** — 번역본을 보면 판정이 쉬워지는 대신 번역 과정에서 표현이 뭉개져 위반 여부가 흐려집니다. 그래서 원문(베트남어 등) 기준으로 판정하고 결과만 한국어로 병기하기로 했습니다. JB금융은 외국인 대출이 1조 규모라 외국어 심의가 영업의 전제인데 지금은 담당자가 언어를 못 읽어 외부 번역을 거치며 수일에서 수주가 밀리고 그 사이 미심의 리스크가 쌓인다는 문제에서 나온 판단입니다.
- **환각을 어디까지 막을 수 있다고 말할 것인가** — 인덱스 그라운딩 검증이 막는 것은 존재하지 않는 조항 번호를 인용하는 구조 환각까지이고, 조항은 실재하는데 해석이 틀린 내용 환각은 규칙엔진과 HITL로 보강한다고만 적었습니다. 제안서가 스스로 그은 선이라 그 선을 넘겨 말하지 않는 것이 맞다고 생각합니다.
- **자기수정 재시도를 몇 번까지 둘 것인가** — 가짜 조항이면 폐기하고 ③판단으로 되돌려 다시 판정하되 상한을 두 번으로 뒀습니다. 무한 루프와 지연을 막는 대신 두 번 안에 근거를 못 찾은 판정은 그대로 남는다는 것을 받아들였습니다.
- **문제를 "검수 부재"로 볼 것인가 "속도"로 볼 것인가** — 처음에는 검수 과정이 허술한 문제라고 생각했는데 스타벅스 사례를 보니 검수는 있었고 프로모션 물량이 연간 222건, 이틀에 1건꼴에 지난달 동시 16건까지 가면서 내부 검수 속도를 추월한 것이었습니다. 그래서 문제를 속도로 다시 정의했고, AI로 생성이 빨라지면서 병목이 검수로 옮겨갔다는 기대효과 절의 프레이밍과 페리카나 AI 광고 논란(2026.5)이 그 연장선입니다.

### 예상 질문

1. **Q:** (L1) 이 시스템을 챗봇이 아니라 Agent라고 부르시는 근거가 무엇인가요?
   **A:** 제안서가 든 차별점은 넷입니다. 원문 직접 심의, 규칙과 LLM 하이브리드, 근거 검증과 자기수정, HITL 루프입니다. 챗봇은 질문에 답만 하지만 이 시스템은 콘텐츠를 입력받아 수집·검색·판단·검증·생성까지 여러 단계를 스스로 수행하고, 중간에 인용 조항이 가짜면 스스로 폐기하고 두 번까지 다시 판정하며, 마지막에 사람 앞에서 멈춰 승인이나 반려, 코멘트를 받아 최종본을 다시 만듭니다. 다만 행동 순서는 모델이 정하지 않고 LangGraph 그래프로 고정돼 있어서, 자율성이 아니라 다단계 실행과 자기수정을 근거로 든 것입니다.
   **꼬리:** 행동 순서를 모델이 정하지 않는다면 자율 에이전트와 워크플로의 경계는 어디에 있을까요?
   **틀리기 쉬운 답:** "LLM을 여러 번 부르면 에이전트"라고 답하는 경우가 있는데, 실제로는 호출 횟수가 아니라 스스로 판단을 되돌리고 멈추는지가 기준입니다.
2. **Q:** (L2) 규정 데이터가 6건인데 Chroma 벡터 검색을 붙이셨습니다. 규칙이나 전체 주입으로도 되지 않았을까요?
   **A:** 제안서에 그 판단 근거는 적혀 있지 않고 스택에 "Chroma + text-embedding-3-small"이 나열되어 있을 뿐입니다. 지금 다시 설계한다면 6건 수준에서는 전체를 컨텍스트에 넣거나 조항 단위 규칙 매핑으로도 되고, 벡터 검색은 규정 수가 늘어날 것을 전제한 선택이었다고 말씀드리는 것이 정직하다고 생각합니다. 다만 규정 문서는 용어가 비슷해도 조항별로 적용 대상이 달라서 의미검색만 믿으면 엉뚱한 조항을 근거로 끌어올 수 있고, ④검증에서 인용 조항을 reg_index와 대조하게 한 것이 그 위험에 대한 대응입니다.
   **꼬리:** 규정이 6건에서 600건이 되면 ②검색과 ④검증 중 어디를 먼저 고치시겠어요?
   **틀리기 쉬운 답:** "RAG니까 당연히 벡터DB가 필요하다"고 답하는 경우가 있는데, 실제로는 코퍼스가 작을수록 검색기가 더할 가치가 줄어듭니다.
3. **Q:** (L2) "필수고지 누락 0% 놓침 보장"이라고 쓰셨는데, 무엇을 근거로 보장이라고 말할 수 있나요?
   **A:** 규칙엔진이 결정론적으로 포착하기 때문이라는 것이 제안서의 논리입니다. 규칙에 적힌 필수고지 항목이 콘텐츠에 없으면 반드시 잡힌다는 뜻이지 모든 법적 누락을 잡는다는 뜻은 아닙니다. 규칙에 없는 항목은 규칙엔진이 못 잡고 LLM 판정에 의존하게 됩니다. recall이 생명인 컴플라이언스라서 결정론 쪽에 누락 탐지를, 확률론 쪽에 과장·오해 표현의 뉘앙스를 맡긴 분업이고, 두 쪽이 같은 위반을 잡으면 이중 적발을 자동 병합합니다. 실측으로 확인한 수치가 아니라 설계상의 성질입니다.
   **꼬리:** 규칙과 LLM이 같은 문구에 서로 다른 심각도를 매기면 어떻게 병합하시나요?
   **틀리기 쉬운 답:** "100% 보장"을 성능 실측처럼 답하는 경우가 있는데, 실제로는 데모 판정의 신뢰도 100%/95%/88%도 화면 예시이지 측정된 정확도가 아닙니다.
4. **Q:** (L3) 이 서비스를 실제 금융사에 도입한다면 가장 큰 장벽이 무엇일까요?
   **A:** 책임 소재라고 생각합니다. 그래서 설계 자체가 HITL로 답합니다. AI가 근거와 심각도, 수정안을 정리해도 최종 결정과 책임은 준법관리자에게 남고, 그것을 문서 원칙이 아니라 그래프의 정지 자리로 강제합니다. 다만 여기에 역설이 있습니다. AI가 1차로 잘 정리할수록 사람은 검토를 형식적으로 하게 되고, 그때 내용 환각(조항은 실재하는데 해석이 틀린 경우)은 그대로 통과합니다. 제안서는 내용 환각을 규칙엔진과 HITL로 보강한다고만 적었으니, 사람 검토가 무뎌지는 경우에 대한 대책은 자료에 없습니다.
   **꼬리:** 사람이 형식적으로 승인하는 것을 시스템이 감지하려면 무엇을 기록해야 할까요?
   **틀리기 쉬운 답:** "사람이 최종 승인하니 법적 책임 문제는 해결된다"고 답하는 경우가 있는데, 실제로는 책임 귀속과 실제 오류 감소가 다른 문제입니다.
5. **Q:** (L3) "심의 리드타임 주~월에서 분 단위로", "올리면 1분 이내"라는 수치는 어떻게 나온 건가요?
   **A:** 제안서의 기대효과 서술이고 실측인지는 자료에 없습니다. 비교 대상인 "주~월"은 지금의 1인 수작업 심의와 외국어 외부 번역 지연을 가리키고, "분 단위"는 여섯 단계를 자동 수행했을 때의 목표입니다. 실제로는 ①수집의 비전 호출, ②검색, ③판단, ④검증의 재판정 루프, ⑤생성이 차례로 이어져 콘텐츠 하나당 모델 호출이 여러 번 들어가고 재판정이 걸리면 그만큼 늘어납니다. ⑥검토는 사람 대기 시간이라 전체 리드타임에는 여전히 사람이 들어갑니다. AI 1차 심의가 분 단위라는 뜻이지 심의 완료가 분 단위는 아닙니다.
   **꼬리:** 그러면 실제로 줄어드는 시간은 어느 구간인가요? 그걸 측정하려면 무엇을 기록해야 할까요?
   **틀리기 쉬운 답:** "1분 이내"를 측정된 응답 시간처럼 답하는 경우가 있는데, 실제로는 제안서의 목표 서술입니다.

### 솔직하게 말할 것

- 원자료가 예선 MVP 제안서 PDF 한 건입니다. 회고도 실패 기록도 없고 로컬 폴더에는 제안서만 있으며 코드는 저장소(https://github.com/accidentable/my-hack)에만 있어서, 어디까지 돌아가는지 물으시면 저장소를 열어 확인해야 한다고 말씀드려야 합니다.
- 심의 리드타임 "주~월 → 분 단위", "1분 이내", 신뢰도 100%/95%/88%는 제안서의 기대효과 서술과 화면 예시라 실측인지는 자료에 없습니다.
- "구조 환각 100% 차단"은 인용 조항 번호가 reg_index에 실재하는지만 보는 검사입니다. 조항 해석이 틀린 내용 환각은 막지 못하고 규칙과 HITL로 보강한다고만 적혀 있습니다.
- 규정 데이터가 금소법 광고규제 핵심 6건이고 데모 언어가 베트남어와 한국어로 한정된 MVP 범위입니다. 다국어 심의가 된다고 말씀드리면 그다음 언어에서 무너집니다.
- Chroma와 임베딩 모델, gpt-5.4 계열, FastAPI, Next.js를 고른 근거가 제안서에 없습니다. 왜 이걸 썼느냐고 물으시면 문서에 근거가 없다고 말씀드리고 지금 시점의 제 판단으로 답하는 편이 낫다고 생각합니다.
- 기간과 결과(수상 여부), 팀 외 기여자 여부가 자료에 없습니다. 팀명 쌀과자, 팀원 1인으로만 적혀 있습니다.
- 향후 확장으로 든 "심의 내용을 반영한 콘텐츠 재생성", "맥락까지 이해하는 AI Agent"는 목표이고 구현하지 않았습니다.
