# 2026 뉴스빅데이터 해커톤 — 끝물레이더

## 1. 개요

- 대회명: 2026 뉴스빅데이터 해커톤
- 참가 부문: 일반 부문 / 출품 유형: 신규 서비스
- 아이디어명: "끝물레이더 : 뉴스 공급신호로 읽는 디저트 유행 생애주기 판정·포화 경보 서비스"
- 제출물: 아이디어 기획서(7쪽 이내, PDF 제출). 본선 기간 2026. 10. 12. ~ 10. 30.
- 결과(수상 여부): 자료에 없음
- 팀명·팀원 이름: 자료에 없음(양식에 `[팀명 입력]`, `[이름]`으로 비어 있음)

## 2. 문제 정의

한 문장으로: "줄 서는 게 보일 때 창업하면, 이미 끝물이다."

디저트 유행의 수명이 짧아지면서, 유행이 눈에 보이는 시점(오픈런·품절)에 진입한 소상공인이 인테리어·가맹비·원재료 선매입 비용을 회수하기 전에 수요가 꺼지는 일이 반복된다. 창업 결정은 "인기가 보일 때" 이뤄지는데 그 시점이 대개 공급 과잉 직전이고, 지금이 유행의 어느 단계인지 판단할 객관적 근거가 없다는 것이 문제의 본질이다.

원자료가 든 사례 둘.

- 탕후루: 2023년 1,300여 곳 신규 개업 → 2024년 상반기 신규 개업 50곳. 폐업은 2023년 72곳 → 2024년 6월 말까지 190곳.
- 두바이 쫀득 쿠키(두쫀쿠): 판매 매장 월평균 판매량이 2025년 말 정점 후 2026년 1월 급감(한국신용데이터 분석), 2월에는 고가에 원재료를 대량 매입한 자영업자들의 재고 처분 호소가 보도됨.

기존 지표의 한계도 같이 정리돼 있다. 검색량·SNS 언급량은 관심의 크기만 보여주고 정점은 지나고 나서야 확인된다. 인허가 폐업 통계·카드매출 리포트는 결과를 집계하는 후행 지표라 확인 시점에는 이미 손실이 난 뒤다.

**뉴스를 쓰는 이유**: 포화는 수요가 아니라 공급 측 사건이다. 편의점·대형마트 유사상품 출시, 프랜차이즈 확장, 원재료 가격 급등·급락, 할인·폐업은 SNS가 아니라 뉴스에 날짜와 함께 기록된다. 기사량·연관어·기관 개체명 같은 정형화된 분석 결과를 빅카인즈 API로 적법하게 수집할 수 있다(크롤링 없음). 이 발상은 [[supply-side-fad-signal]]로 따로 정리했다.

## 3. 접근

### 3-1. 서비스 개요

디저트 키워드를 입력하면 뉴스 신호로 태동·확산·포화·쇠퇴 중 현재 단계를 판정하고, 판정 근거가 된 기사를 함께 보여주며, 포화 단계에 진입하면 경보를 보내는 웹 서비스.

이용 흐름: ① 키워드 입력(예: 두쫀쿠) → ② 동의어 통합(두쫀쿠 = 두바이 쫀득 쿠키) → ③ 단계 게이지·신뢰도·판정 사유 확인 → ④ 근거 타임라인·기사 확인 → ⑤ 관심 키워드 등록 → ⑥ 포화 진입 시 이메일 경보.

### 3-2. 핵심 기능 4가지

| 기능 | 내용 |
| --- | --- |
| 생애주기 판정 | 기사량·연관어·기관 3개 신호를 결합해 현재 단계와 신뢰도(높음/보통/낮음), 판정 사유 표시 |
| 근거 타임라인 | 기사량 곡선 위에 신호 발생 시점(유통사 첫 등장, 연관어 역전 등)을 표시하고, 해당 기사의 제목·언론사·날짜·본문 앞 200자를 근거 카드로 제공 |
| 과거 유행 겹쳐보기 | 현재 곡선을 탕후루·두쫀쿠 등 과거 곡선과 정점 기준으로 겹쳐 "과거 ○○의 어느 시점과 닮았는지" 제시 |
| 포화 경보 | 매일 판정을 갱신하고, 단계가 포화로 바뀌는 순간에만 알림(새 기사마다 오는 알림과 구분) |

### 3-3. 이용자와 필요한 정보

| 이용자 | 내려야 하는 결정 | 필요한 정보 |
| --- | --- | --- |
| 예비창업자·소상공인 | 품목 선택, 진입 여부 | 현재 단계와 판단 근거 |
| 기존 카페·베이커리 | 신메뉴 도입, 원재료 매입량 | 포화 진입 경보 |
| 유통·편의점 MD, 식자재 유통 | 출시·발주 타이밍 | 단계 전환 시점 |
| 소상공인 지원기관·창업교육 | 교육·컨설팅 자료 | 과거 유행 사례 비교 |

### 3-4. 사용 데이터

- 빅카인즈 뉴스데이터(API): 일별 기사량, 연관어·가중치, 기관 개체명, 기사 메타정보·본문 앞 200자 → 단계 판정 신호와 근거 기사 제시. 활용 방법은 [[bigkinds-api]].
- 행정안전부 지방행정인허가 데이터: 휴게음식점·제과점 개·폐업(상호명에 품목명이 포함된 매장 집계) → 판정 정확도 검증용 정답 기준.
- 유통사·프랜차이즈 사전(자체 구축): 편의점·대형마트·주요 디저트 프랜차이즈명 → 포화 신호(기관 첫 등장) 탐지.

### 3-5. 단계 판정 규칙 (초기안, 임계값은 본선 백테스트로 조정)

| 단계 | 기사량 신호 | 연관어 신호 | 기관 신호 |
| --- | --- | --- | --- |
| 태동 | 기사 수 적음, 증가 시작 | 신호어 미미 | 대형 유통 미등장 |
| 확산 | 4주 증가율 급상승 | 흥행어 비중 증가 | 대형 유통 미등장 |
| 포화 | 정점 부근 유지 | 흥행어 비중 정체 | 편의점·대형마트·프랜차이즈 첫 등장 |
| 쇠퇴 | 정점 대비 감소 지속 | 쇠퇴어가 흥행어를 역전 | 유통 할인·철수 기사 증가 |

신뢰도는 세 신호가 일치할수록 높게 표시하고, 기사 수가 적은 태동 단계는 "낮음"으로 표시한다.

### 3-6. 기술 스택과 역할 분담

- 스택: Python(pandas, FastAPI), PostgreSQL, Next.js, 일 1회 배치 작업, 이메일 발송.
- 빅카인즈 API: 기사량·연관어·기관 개체명·기사 메타정보 수집.
- 규칙 기반 판정 엔진(Python): 지표 계산과 단계 판정. 사람이 설명할 수 있도록 규칙으로 구성.
- 생성형 AI(LLM): 동의어·줄임말 통합, 사전에 없는 새 연관어를 흥행/포화/쇠퇴 신호로 분류, 근거 문장 선택과 판정 사유 한 줄 요약. **단계 판정 자체는 LLM이 하지 않는다.**
- 웹·스케줄러: 결과 시각화, 일 1회 판정 갱신 및 경보 발송.

팀은 4명 구성(팀장: 기획 총괄·판정 규칙 설계·사례 검증 / 빅카인즈 연동·판정 엔진·백테스트 / 백엔드·LLM 연동 / 프론트엔드·시연 영상). 이름은 자료에 없음.

### 3-7. 검증 계획 (본선 백테스트)

과거 데이터에 판정 규칙을 적용해 당시 경보가 제때 울렸을지 확인한다.

- 대상: 크로플, 탕후루, 두바이 초콜릿, 두바이 쫀득 쿠키 + 대조군(수요가 장기간 유지된 품목 1~2개. 경보가 울리지 않아야 정상).
- 정답 기준: 지방행정인허가 데이터상 폐업 급증 시점, 보도된 판매량 급감 시점.
- 평가 지표: ① 리드타임(포화 경보일부터 폐업 급증 시점까지의 간격) ② 대조군 오경보 여부 ③ 단계 순서 일치 여부.

### 3-8. 본선 일정과 목표 수준

대회 참가 전 구현 현황은 전 항목 "해당 없음"(신규 서비스). 네 개 모듈 모두 미구현 상태에서 시작한다.

| 주차 | 내용 |
| --- | --- |
| 1주차 (10.12~10.16) | API 연동, 사례·대조군 데이터 적재, 유통사·프랜차이즈 사전 구축 |
| 2주차 (10.19~10.23) | 판정 엔진 구현, 백테스트 및 임계값 조정, LLM 신호 분류 적용 |
| 3주차 (10.26~10.30) | 웹 UI·경보 구현, 시연 영상·GIF·화면 캡처 제작, 발표 자료 작성 |

본선 종료 시 목표: 임의의 디저트 키워드를 넣으면 실제 빅카인즈 API 데이터로 단계·근거 기사·타임라인이 표시되는 웹 프로토타입, 사례 4종과 대조군의 백테스트 결과표, 시연 영상.

## 4. 잘된 점 / 안된 점

이 자료는 대회 전 아이디어 기획서이므로 실행 결과에 대한 회고는 자료에 없음. 기획서가 스스로 밝힌 강점과 한계만 옮긴다.

**강점(기획서가 주장한 차별점)**

- 관심의 크기가 아니라 **공급 측 사건의 순서**로 단계를 판정하는 접근.
- 모든 판정에 근거 기사를 붙여 사용자가 직접 확인 가능한 설명 가능한 규칙 기반 판정.
- 과거 유행 곡선과 겹쳐 보여줘 데이터에 익숙하지 않은 소상공인도 위치를 직관적으로 이해.

기존 도구와의 대비표:

| 구분 | 보여주는 것 | 한계 | 끝물레이더 |
| --- | --- | --- | --- |
| 검색량 트렌드 도구 | 관심의 크기 | 단계 판단·근거 없음, 정점은 사후 확인 | 단계 판정 + 근거 기사 |
| 소셜 분석 도구 | 언급량·감성 | 수요 측 신호만 관찰 | 공급 측 신호(유통 진입·가격·폐업) 관찰 |
| 상권·인허가 통계 | 업종별 개·폐업 수 | 후행 지표, 업종 단위(품목 구분 불가) | 품목 단위 선행 경보 |
| 뉴스 키워드 알림 | 새 기사 등록 알림 | 상태 판단 없음, 알림 과다 | 단계 전환 시에만 경보 |

**한계와 대응(기획서 ⑥항)**

- 뉴스는 SNS보다 태동 포착이 늦다 → 태동 판정은 신뢰도 "낮음"으로 표시하고, 서비스의 핵심 가치는 포화·쇠퇴 경보에 둔다.
- 동명이의어·광고성 기사 → 동의어 사전과 LLM 필터로 보정.
- 판정 결과는 참고 정보이며 창업·투자 결정의 책임은 이용자에게 있음을 서비스 내 고지.
- 빅카인즈에서 기관 개체명 필드가 제공되지 않을 경우 → 기사 제목·본문 앞 200자에서 유통사 사전을 매칭하는 방식으로 대체.

## 5. 기대효과와 확장

- 예비창업자: 창업 전 현재 단계를 근거 기사와 함께 확인해 정점 직전 과잉 진입 회피. 기존 매장: 원재료 선매입·신메뉴 투자 규모 조절로 재고 손실 감소. 유통·MD·식자재: 출시·발주·재고 축소 타이밍 보조.
- 사회적 효과: "유행 편승 창업 → 단기 폐업" 반복 완화, 소상공인 지원기관 창업교육·컨설팅에 객관적 자료 제공.
- 데이터 융합 효과: 뉴스(원인·맥락)와 인허가 데이터(결과)를 결합해 뉴스 신호가 실제 폐업보다 얼마나 앞서는지 수치로 검증.
- 사업화: 개인 대상 단계 조회 무료, 유통사·식자재·프랜차이즈 본사 대상 경보·리포트는 구독형(B2B). 지자체·지원기관 창업지원 포털 연계. 디저트 → 외식 메뉴 전반 → 패션·뷰티로 확장.

## 6. 재사용 가능한 것

구현물이 아직 없으므로 재사용 대상은 자료와 설계다.

- 단계 판정 규칙표(3-5절)와 백테스트 설계(3-7절): 다른 "유행 조기경보" 과제에 그대로 이식 가능.
- 유통사·프랜차이즈 사전(편의점·대형마트·주요 디저트 프랜차이즈명): 자체 구축 예정, 아직 없음.
- 두쫀쿠 공개 보도 타임라인(아래 7절): 가설 검증용 사례 자료.
- 참고 출처: 세계일보(2024.6.30.), kbc광주방송(2024.6.24.) — 행정안전부 지방행정인허가 데이터 인용 탕후루 개·폐업 현황 / 아시아경제(2026.2.7., 2026.2.17., 2026.3.9.) — 두쫀쿠 유통사 출시, 재고·가격 하락, 한국신용데이터 판매량 분석 / 서울신문(2026.3.9.) — 한국신용데이터 소상공인 동향 리포트.
