# TACO Index (타코알리미)

## 1. 개요

- 기간: 2026-03-25 첫 커밋 ~ 2026-03-30 마지막 커밋 (git log 43개 커밋 기준). 약 6일.
- 주제: 트럼프의 대이란 강경책 번복("TACO", Trump Always Chickens Out) 가능성을 시장지표 6개로 점수화해 실시간으로 보여주는 웹 대시보드.
- 서비스 도메인: `tacotrump.space`. 저장소 https://github.com/accidentable/tacotrump
- 결과: **해커톤 여부 자료에 없음(개인 프로젝트 추정)**. 대회명, 수상, 제출 기록이 원자료에 전혀 없다. 광고(AdSense), SEO(sitemap/robots/JSON-LD/hreflang), 방문자 카운터, 공유 버튼 등 일반 공개 서비스 운영 흔적만 있다.

## 2. 문제 정의

"트럼프가 이번에도 물러날까"라는 질문은 뉴스 논평으로만 소비되고, 판단 근거가 흩어져 있다. 이 프로젝트는 그 질문을 **관측 가능한 시장 압력 지표의 합**으로 바꿔서 0~6점 한 숫자와 레벨 1~4로 보여준다. 트럼프 본인의 발언이 아니라 그를 압박하는 시장 쪽을 본다는 것이 설계의 핵심이다.

커밋 기록을 보면 대상 맥락이 두 번 바뀌었다. 처음에는 관세 맥락이었다가 `fix: 관세→이란-미국 전쟁 맥락으로 설명 전체 수정`(03-27)으로 옮겼고, 6분 뒤 `fix: 문구를 TACO 일반 개념(시장 압박→후퇴)으로 재수정`으로 다시 일반화했다. 지표 자체는 그대로 두고 설명 문구만 갈아 끼웠다(추정: 지표가 특정 사건에 묶여 있지 않아 가능했다).

## 3. 접근

### 3.1 지표와 점수

핵심 6개 지표. 각각 "안전값(safe)"과 "레드라인(redline)"을 두고 그 사이를 선형 보간해 0~1점을 매긴 뒤 단순 합산한다(가중치 없음, 만점 6.0).

| 키 | 지표 | 티커/출처 | safe | redline | 방향 |
| --- | --- | --- | --- | --- | --- |
| `sp500` | E-mini S&P 선물 52주 고점 대비 하락률(%) | `ES=F` (Yahoo) | -3.0 | -15.0 | below |
| `vix` | VIX 공포지수 | `^VIX` | 15.0 | 35.0 | above |
| `treasury_10y` | 미 10년물 국채금리(%) | `^TNX` | 4.0 | 4.5 | above |
| `oil` | 유가 WTI($/배럴) | `CL=F` | 75.0 | 100.0 | above |
| `dollar_index` | 달러 인덱스 | `DX-Y.NYB` | 97.0 | 110.0 | above |
| `approval_rating` | 대통령 지지율(%) | RealClearPolling 스크래핑 | 50.0 | 35.0 | below |

확장 지표 3개(`gasoline` FRED `GASREGW`, `treasury_30y` `^TYX`, `russell2000` `^RUT`)는 화면에 참고로 보여주되 총점에는 넣지 않는다.

총점 → 레벨: `<1.8` Lv.1 안전, `<3.0` Lv.2 주의, `<4.2` Lv.3 경고, 그 이상 Lv.4 위험. 각 레벨에 라벨·색·한국어 설명("시장 패닉. 트럼프 후퇴(타코) 임박.")이 붙는다.

지표 설계 자체는 [[market-redline-composite-score]]에 따로 정리했다.

### 3.2 아키텍처: 백엔드가 둘이다

같은 점수 로직이 두 곳에 **복제**되어 있다.

- `backend/`: FastAPI + APScheduler + aiosqlite + WebSocket. 1분마다 `collect_all_data()`가 돌면서 SQLite(`indicator_history`, `latest_indicators`)에 적재하고 WebSocket으로 브로드캐스트한다. 로컬 개발/전체 기능판(추정).
- `api/`: Vercel 파이썬 서버리스 함수 7개(`BaseHTTPRequestHandler` 직접 구현, 프레임워크 없음). 요청마다 Yahoo와 RCP를 실시간 fetch하고 `Cache-Control: s-maxage=...`로 엣지 캐시에 맡긴다. DB도 스케줄러도 없다. 실제 배포판.

`score_engine.py` 상단 주석이 "(Vercel 배포 버전과 동기화)"라고 스스로 밝힌다. 이 이중 구조의 득실은 [[dual-backend-local-vs-serverless]]에 정리했다.

### 3.3 프론트

React 19 + Vite 8 + TypeScript + Tailwind 4 + recharts. 컴포넌트는 GaugeBar, RiskCard, IndicatorGrid/IndicatorCard, ExtendedIndicators, HistoryTimeline, TruthFeed, ShareButton, NotificationCTA. 훅으로 `useIndicators`, `useTruths`, `usePageViews`, `useWebSocket`. i18n은 자체 구현(`i18n/ko.ts`, `en.ts`). 커밋 `feat: 토스 스타일 UI 리디자인`(03-27)으로 디자인을 한 번 갈아엎었다.

레벨별 트럼프 이미지(`level1_1.png`~`level4_2.png`, `print1`~`print10`)를 띄우는데, 도중에 `UI: 레벨 상관없이 전체 이미지 랜덤 표시`로 레벨-이미지 연결을 끊었다.

### 3.4 알림·크론

`vercel.json`의 `crons`로 `/api/cron/check-level`을 `0 * * * *`(매시)에 호출한다. 이 함수가 현재 레벨을 계산해 Redis의 `push_last_level`과 비교하고, **바뀐 경우에만** `push_subs` 셋에 있는 구독 전체에 pywebpush로 Web Push를 쏜다. 410 응답이 온 구독은 셋에서 제거한다. 요청은 `Authorization: Bearer <CRON_SECRET>`으로 검증한다. 자세한 건 [[vercel-python-cron-webpush]].

크론 주기는 `하루 1회로 변경 (Hobby 플랜 제한)`(03-27) → `하루 1회 → 매시간으로 변경`(03-30)으로 왕복했다.

### 3.5 부가 기능

- `/api/truths`: trumpstruth.org RSS를 defusedxml로 파싱해 트럼프 Truth Social 글을 가져오고, OpenAI `gpt-4o-mini`로 **한 번의 호출에 전부 묶어** 15~30자 한국어 헤드라인으로 요약한다(`[번호]` 프로토콜로 입출력 매칭). 키가 없으면 원문 그대로 반환. maxDuration 60초.
- `/api/pageviews`: Upstash/Vercel KV REST `incr`로 방문자 카운터. 환경변수 이름 4가지 패턴을 or로 훑는다(`fix: Redis 환경변수 다중 패턴 대응`).
- 보안: 03-29 `security:` 커밋 하나로 CORS 화이트리스트(`tacotrump.space`, `localhost:5173`), 에러 메시지 제거(모두 "Internal server error"), 푸시 구독 바디 4KB 제한과 필드 검증, `X-Frame-Options`/`HSTS`/`Referrer-Policy` 등 보안 헤더를 한꺼번에 넣었다.

## 4. 잘된 점 / 안된 점

### 잘된 점
- **한 숫자로 요약되는 컨셉**이 공유·바이럴과 잘 맞았다. 공유 버튼, OG 이미지, 레벨 팝오버 설명, 푸시 알림이 전부 "지금 몇 레벨?"이라는 한 질문에 수렴한다.
- **무료 데이터만으로 굴러간다.** Yahoo Finance v8 chart 엔드포인트, FRED, RCP 스크래핑 모두 무과금이고, 모든 fetch에 fallback 상수가 있어 외부가 죽어도 화면이 빈 채로 멈추지 않는다.
- **엣지 캐시로 서버 없이 버틴다.** 서버리스 함수가 상태를 안 가지고 `s-maxage`(risk 30초, truths 120초, history 300초)로 Yahoo 호출량을 눌렀다.
- 보안 강화를 한 커밋으로 몰아서 정리한 것, 만료된 푸시 구독(410)을 자동 청소하는 것은 깔끔하다.

### 안된 점
- **점수 로직 복제로 두 판이 이미 어긋났다.** `backend/`의 `data_collector.py`는 `core_values`를 만들 때 `approval_rating`을 빼고 5개만 넣는데, 총점은 여전히 만점 6.0 기준으로 레벨을 가른다. 즉 로컬판은 구조적으로 점수가 낮게 나온다. `api/_shared.py`는 6개를 다 넣는다. Lv.1 색도 `#16A34A`(backend) vs `#3CD5AF`(api)로 다르다.
- **주석이 코드와 안 맞는다.** `api/_shared.py`의 `calc_indicator_score`는 `# S&P 500: safe=-5, redline=-20`이라고 써 있지만 실제 상수는 `safe=-3.0, value=-15.0`이다. 임계값을 조정하면서 주석만 안 고쳤다(추정).
- **지지율에 과거 데이터가 없다.** `/api/history`는 "지지율은 과거 데이터 없으므로 현재값을 전 구간에 적용"한다고 명시한다. 따라서 히스토리 차트의 과거 총점은 지지율 항이 오늘 값으로 고정된 반사실적 값이다.
- **히스토리와 실시간의 S&P 티커가 다르다.** 실시간은 `ES=F`(E-mini 선물), 히스토리는 `^GSPC`(현물 지수)를 쓴다. 같은 축에 그려지지만 소스가 다르다.
- **RCP 지지율 스크래핑이 깨지기 쉽다.** `rcp_average` 문자열을 찾아 뒤 500자에서 정규식으로 숫자를 뽑는다. 페이지 구조가 바뀌면 조용히 fallback 41.3으로 떨어지고 화면은 정상으로 보인다.
- **레드라인 값의 근거가 코드 어디에도 없다.** VIX 35, 10년물 4.5, 유가 100 같은 숫자가 왜 그 값인지 문서화되어 있지 않다(추정: 감각으로 정한 값).
- `feat: 홈 위젯 기능 추가 (PWA + iOS Scriptable + Widget API)`는 3분 만에 Revert됐다.

## 5. 재사용 가능한 것

경로는 모두 `C:\Users\pc\Desktop\해커톤\tacotrump` 기준.

- `api/_shared.py`: Vercel 파이썬 서버리스에서 쓸 **CORS 헬퍼 + 공통 에러 응답 + Yahoo 병렬 fetch + fallback + 점수 엔진**이 한 파일에 다 있다. 다른 지표 대시보드에 그대로 이식 가능.
- `api/cron/check-level.py`: Vercel Cron + `CRON_SECRET` 검증 + Redis에 이전 상태 저장 + 상태 변화 시에만 Web Push + 410 구독 정리. 상태변화 알림의 최소 완성형.
- `api/push-subscribe.py`: Web Push 구독 POST/DELETE, 바디 크기 제한과 `endpoint`/`keys.p256dh`/`keys.auth` 검증.
- `scripts/generate-vapid.py`: VAPID 키 생성.
- `backend/app/services/yahoo_fetcher.py`: yfinance 없이 httpx로 Yahoo v8 chart를 직접 병렬 호출. 52주 고점 대비 하락률 계산 포함.
- `api/truths.py`의 `translate_posts()`: 여러 건을 `[번호]` 마커로 묶어 LLM 호출 1회로 처리하고 정규식으로 되돌리는 배치 번역 패턴.
- `api/history.py`의 forward-fill 구간: 티커마다 거래일이 다를 때 날짜 축을 합치고 빈 칸을 직전 값으로 채운 뒤, 모든 지표가 채워진 날만 남긴다.
- `vercel.json`: 프론트 빌드 + 파이썬 함수 + 크론 + 보안 헤더를 한 파일에 묶은 예시.

### 아키텍처

- [client] 대시보드 :: React 19, Vite 8, TypeScript, Tailwind 4, recharts :: Vercel, `tacotrump.space`
- [server] 서버리스 API :: 파이썬 함수 7개, `BaseHTTPRequestHandler`, `s-maxage` 엣지 캐시 :: Vercel
- [ops] 레벨 점검 크론 :: Vercel Cron `0 * * * *`, `/api/cron/check-level`, `CRON_SECRET` 검증 :: Vercel
- [data] 상태 저장소 :: Redis REST, `push_last_level`, `push_subs`, 방문자 카운터 :: Upstash 또는 Vercel KV

- [external] 웹 푸시 :: pywebpush, VAPID :: 브라우저 푸시 서비스

- 대시보드 -> 서버리스 API :: 지표·총점·히스토리·Truth 조회
- 서버리스 API -> 시장 데이터 원천 :: 티커별 병렬 fetch, 실패 시 fallback 상수
- 서버리스 API -> Truth 요약 :: RSS 글을 `[번호]` 마커로 묶은 요약 요청
- 서버리스 API -> 상태 저장소 :: 푸시 구독 등록·삭제, 방문자 수 `incr`
- 레벨 점검 크론 -> 시장 데이터 원천 :: 현재 지표 조회와 레벨 계산
- 레벨 점검 크론 -> 상태 저장소 :: 이전 레벨 비교·갱신, 구독 셋 조회와 410 제거
- 레벨 점검 크론 -> 웹 푸시 :: 레벨이 바뀐 경우에만 구독 전체 직렬 발송
- 로컬 전체 기능판 -> 시장 데이터 원천 :: 1분 주기 수집

### 고민한 점

- **무엇을 재는 지수인지가 두 번 바뀌었다** — 관세 맥락으로 시작했다가 `fix: 관세→이란-미국 전쟁 맥락으로 설명 전체 수정`(03-27)으로 옮겼고, 6분 뒤 `fix: 문구를 TACO 일반 개념(시장 압박→후퇴)으로 재수정`으로 다시 넓혔습니다. 지표는 손대지 않고 설명 문구만 갈아 끼웠는데, 지표가 특정 사건에 묶여 있지 않아 가능했다는 것은 추정입니다.
- **지표 구성을 바꿀 것인가** — `feat: S&P→E-mini 선물(ES=F) 변경 + VIX 공포지수 추가`(03-27)로 실시간 쪽을 바꿨습니다. 히스토리는 `^GSPC` 현물을 그대로 두는 바람에 같은 축에 다른 소스가 그려지는 상태가 남았습니다.
- **알림을 언제 보낼 것인가** — 매 실행마다 현재 값을 보내면 알림이 너무 잦겠다 싶어서, Redis에 넣어 둔 이전 레벨과 비교해 바뀐 경우에만 보내기로 했습니다. 그러려면 연속값인 총점을 레벨 1~4로 끊어야 했고, 크론 주기는 Hobby 플랜 제한 때문에 하루 1회로 내렸다가(03-27) 매시간으로 되돌렸습니다(03-30).
- **보안을 언제 할 것인가** — 만들면서 조금씩 하지 않고 03-29에 `security:` 커밋 하나로 CORS 화이트리스트, 에러 메시지 일반화, 푸시 구독 바디 4KB 제한과 필드 검증, `X-Frame-Options`와 HSTS, `Referrer-Policy` 헤더를 한꺼번에 넣었습니다. 배포부터 하고 나중에 몰아서 정리한 방식입니다.
- **넣었다가 도로 뺀 것** — `feat: 홈 위젯 기능 추가 (PWA + iOS Scriptable + Widget API)`가 3분 만에 Revert됐습니다. 레벨별 트럼프 이미지도 `UI: 레벨 상관없이 전체 이미지 랜덤 표시`로 레벨과 이미지의 연결을 끊었습니다.

### 예상 질문

1. **Q:** (L1) 이 대시보드가 보여주는 숫자는 무엇을 뜻하나요. 무엇을 예측한다고 말할 수 있고 말할 수 없나요?
   **A:** 지표 여섯 개가 각각 안전값에서 레드라인까지 어디쯤 와 있는지를 0~1로 바꿔 그냥 더한 값입니다. 만점이 6.0이고 1.8, 3.0, 4.2를 경계로 레벨 1~4가 갈립니다. 그러니까 이 숫자가 말하는 건 지금 시장 압력 지표들이 위험 구간에 얼마나 가 있느냐이지 트럼프가 물러날 확률이 아닙니다. 설계의 출발점도 트럼프의 발언이 아니라 그를 압박하는 시장 쪽을 보자는 것이었습니다. 이름에는 "번복 가능성 지수"라고 붙였지만 이 점수를 실제 번복 사건과 맞춰 본 기록은 코드에도 자료에도 없습니다.
   **꼬리:** 그러면 확률처럼 읽히는 이름과 "트럼프 후퇴 임박" 같은 레벨 문구는 정당한가요?
   **틀리기 쉬운 답:** "머신러닝으로 확률을 예측합니다"라고 답하는 경우가 있는데, 실제로는 학습도 예측 모델도 없고 규칙으로 정한 정규화와 합산이 전부입니다.
2. **Q:** (L2) 6일에 43커밋으로 혼자 만드셨는데, 무엇을 의도적으로 안 하셨고 그 대가가 어디에 나타났나요?
   **A:** 테스트를 아예 쓰지 않았고, 두 백엔드의 점수 로직을 공유 패키지로 빼지 않고 복제했습니다. 대가는 세 군데에 나왔습니다. 먼저 로직이 표류했는데, `backend/`의 `data_collector.py`는 `core_values`에 `approval_rating`을 빼고 다섯 개만 넣으면서 레벨은 여전히 만점 6.0 기준으로 갈라서 로컬판 점수가 구조적으로 낮게 나오고, `api/_shared.py`는 여섯 개를 다 넣습니다. Lv.1 색도 `#16A34A`와 `#3CD5AF`로 다릅니다. 다음으로 주석이 코드와 어긋나서 `calc_indicator_score`에 `# S&P 500: safe=-5, redline=-20`이라 써 있지만 실제 상수는 -3.0과 -15.0입니다. 마지막으로 크론 함수 docstring은 5분마다라고 하는데 `vercel.json`은 `0 * * * *`입니다. 전부 테스트나 단일 출처가 있었으면 걸렸을 것들입니다.
   **꼬리:** 지금 이 코드에 테스트를 딱 하나만 쓴다면 무엇을 쓰시겠어요?
   **틀리기 쉬운 답:** "해커톤 속도라 어쩔 수 없었습니다"로 끝내는 경우가 있는데, 실제로는 무엇을 포기했고 그 값을 어디서 치렀는지까지 말해야 판단을 설명한 게 됩니다.
3. **Q:** (L2) 프로젝트 도중 대상 맥락이 관세에서 이란, TACO 일반 개념으로 두 번 바뀌었는데 지표는 손대지 않으셨습니다. 이게 설계의 강점인가요 약점인가요?
   **A:** 양쪽 다라고 생각합니다. 강점은 지표가 특정 사건이 아니라 S&P 하락률과 VIX, 10년물, 유가, 달러 인덱스, 지지율이라는 일반적인 시장 압력이라 맥락이 바뀌어도 그대로 쓸 수 있었다는 점이고, 실제로 03-27에 6분 간격으로 문구만 두 번 갈아 끼웠습니다. 약점은 같은 사실을 뒤집으면 나옵니다. 어떤 사건에도 맞출 수 있다는 건 어떤 사건에도 특별히 맞춰져 있지 않다는 뜻이고, 레드라인 값의 근거가 코드 어디에도 없어서 이 조합이 이란 상황에 적절한 지표냐는 질문에는 댈 재료가 없습니다.
   **꼬리:** 맥락별로 가중치를 달리하려면 무엇부터 정하셔야 할까요?
   **틀리기 쉬운 답:** "범용 지표라 재사용성이 좋습니다"라고만 답하는 경우가 있는데, 실제로 재사용할 수 있는 지표와 특정 질문에 타당한 지표는 다른 이야기입니다.
4. **Q:** (L3) 이 서비스가 틀린 값을 보여주면서도 정상처럼 보이는 경로를 들어 봐 주시겠어요?
   **A:** 적어도 셋 있습니다. 먼저 RCP 지지율 스크래핑인데, `rcp_average` 문자열 뒤 500자에서 정규식으로 숫자를 뽑기 때문에 페이지 구조가 바뀌면 조용히 fallback 41.3으로 떨어지고 화면은 멀쩡해 보입니다. Yahoo와 FRED 쪽도 모두 fallback 상수가 있어 성질이 같습니다. 다음은 히스토리 차트의 지지율인데, `/api/history`가 지지율은 과거 데이터가 없어 현재값을 전 구간에 적용한다고 스스로 밝히고 있어서 과거 총점은 지지율 항이 오늘 값으로 굳은 반사실적 값입니다. 셋째로 실시간은 `ES=F` 선물, 히스토리는 `^GSPC` 현물을 써서 같은 축에 다른 소스가 그려집니다. 여기에 로컬판이 다섯 개만 합산하는 문제까지 더하면 어느 화면을 보느냐에 따라 다른 점수를 보게 됩니다.
   **꼬리:** fallback을 없애는 게 답일까요. 아니라면 무엇을 바꾸시겠어요?
   **틀리기 쉬운 답:** "fallback이 있으니 장애에 강합니다"라고 답하는 경우가 있는데, 실제로 fallback은 가용성을 지키는 대신 실패를 안 보이게 만들었고 이 서비스에는 그 사실을 화면에 알리는 표시가 없습니다.
5. **Q:** (L3) 구독자가 1만 명이 되고 레벨이 자주 바뀌면 어디가 먼저 문제가 될까요?
   **A:** 푸시 발송이 먼저입니다. `check-level.py`가 Redis 셋의 구독을 `for` 루프로 하나씩 `webpush` 호출하는 직렬 구조라 구독 수에 비례해 실행 시간이 늘고 서버리스 함수 실행 시간 제한에 먼저 닿습니다. `vercel.json`에 `maxDuration`이 지정된 함수는 `api/truths.py` 하나뿐입니다. 중간에 끊기면 일부만 받게 되고, 그 실행에서 `r.set(LAST_LEVEL_KEY, ...)`까지 못 가면 다음 실행이 같은 변화를 다시 감지합니다. 그다음이 조회 쪽인데 여기는 상태가 없고 `s-maxage` 엣지 캐시가 Yahoo 호출량을 눌러 주니 사용자 수보다 캐시 만료 주기에 비례합니다. 실행 시간 제한에 먼저 닿는다는 건 코드를 보고 읽은 것이고 실제로 재 본 기록은 자료에 없습니다.
   **꼬리:** 직렬 발송을 그대로 두고 완화하는 방법과 구조를 바꾸는 방법을 각각 말씀해 주시겠어요?
   **틀리기 쉬운 답:** "서버리스라 자동으로 확장됩니다"라고 답하는 경우가 있는데, 실제로 요청당 병렬 확장과 한 실행 안의 직렬 루프는 다른 문제입니다.

### 솔직하게 말할 것

- 해커톤 출품작인지 자료에 근거가 없습니다. 대회명과 수상, 제출 기록이 전혀 없고 광고와 SEO, 방문자 카운터 같은 일반 공개 서비스 운영 흔적만 있어서 개인 프로젝트로 보는 편이 자료에 맞고, 해커톤 프로젝트라고 소개하면 확인할 수 없는 말을 하는 셈입니다.
- 레드라인 값의 근거가 없습니다. VIX 35, 10년물 4.5%, 유가 100달러, 지지율 35% 같은 숫자가 왜 그 값인지 코드에도 문서에도 없고 감각으로 정했다는 것조차 추정이라, 지수의 핵심 파라미터인데 근거를 못 댄다는 점은 제가 먼저 말씀드리는 편이 낫다고 생각합니다.
- 지수가 맞는지 검증한 적이 없습니다. 이 점수가 실제 번복 사건보다 앞섰는지 확인한 백테스트나 사후 검증이 없고, 단순 합산이라 모든 지표에 같은 가중치를 준 셈인데 가중치를 검토한 기록도 없습니다.
- 점수 로직이 두 곳에 복제돼 이미 어긋나 있습니다. 로컬판은 다섯 개만 합산하면서 만점 6.0 기준으로 레벨을 가르고 색상값도 다른데, 배포 당시에 이걸 알고 있었는지는 자료로 확인되지 않아서 몰랐다면 몰랐다고 말씀드리려고 합니다.
- 주석과 문서가 코드와 여러 곳에서 어긋납니다. 점수 함수 주석의 임계값 -5/-20이 실제 상수 -3.0/-15.0과 다르고, 크론 함수 docstring의 5분마다가 실제 설정인 매시간과 다릅니다.
- 히스토리 차트의 과거 총점은 반사실적 값입니다. 지지율 항이 오늘 값으로 고정돼 있다고 `/api/history`가 직접 밝히고 있어서, 이 차트를 근거로 과거에도 이랬다고 말하면 안 됩니다.
- AI 도구가 어디까지 짰는지 기록이 없습니다. 6일 43커밋에 프론트와 서버리스, FastAPI, Web Push, i18n, SEO가 다 들어간 규모인데 생성 범위 기록이 없어서, 직접 설계한 부분인 지표 구성과 레드라인 방식, 변화 시에만 알리는 결정과 손이 덜 간 부분을 미리 나눠 두려고 합니다.
