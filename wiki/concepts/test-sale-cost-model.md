# 시험 판매 비용 계산, 사전 현금과 사용 원가를 분리하기

## 1. 한 줄 정의

신메뉴 소규모 시험 판매를 "지금 나가야 하는 현금"과 "이번 시험에 소비하는 원가"로 갈라 계산하고, 두 값을 손익에서 동시에 차감하지 않도록 규칙으로 못박은 계산 모델. AI 밖의 순수 함수로 둔다.

## 2. 어디서 썼는가

- [[im-challenge-daegu-2026-sns-menu]], SNS 신메뉴 AI 컨설팅의 F07. 구현은 `src/domain/cost.ts`(독립 순수 함수), 단위 테스트 T09~T13. 이 계산이 대회 공모 분야의 "디지털 금융" 연결점 역할을 했다.
- 같은 분업 원칙: [[rule-engine-llm-split]]. 이 프로젝트에서 AI 쪽으로 옮긴 판단은 [[ai-judgement-rule-ceiling]]이고, 비용은 끝까지 옮기지 않았다.

## 3. 실제로 겪은 문제와 해결

**기호.** Q 준비 수량, S 시나리오 판매 수량(0 이상 Q 이하), P 가정 판매가, c 개당 원재료 사용 원가 + 제조 시점 포장비, b 판매 1개당 포장비, r 수수료율, L 준비 인건비, F 일회성 준비비, W 추가 폐기 원가.

**제조 방식에 따라 식이 달라진다.**

```text
주문 후 제조(made_to_order)
  개당공헌이익 = P × (1 − r) − c − b
  시험손익(S)  = S × 개당공헌이익 − L − F − W
  비용회수수량 = ceil((L + F + W) / 개당공헌이익)

Q개 선제조(pre_batch)
  판매1개당추가수입 = P × (1 − r) − b
  시험손익(S)  = S × 판매1개당추가수입 − Q × c − L − F − W
  비용회수수량 = ceil((Q × c + L + F + W) / 판매1개당추가수입)
```

**가장 자주 틀리는 지점: 이중 차감.** 선제조에서는 미판매 완제품 원가가 이미 `Q × c`에 들어 있다. 여기서 미판매분 재료비를 또 빼면 오답이다. 기획서가 예제로 못박았다. Q 30 / S 20 / P 5,000 / c 1,500 / b 300 / L+F 10,000 / r 0 / W 0일 때 선제조 손익은 `100,000 − 45,000 − 6,000 − 10,000 = 39,000원`, 회수 `ceil(55,000/4,700) = 12개`, 주문 후 제조는 `100,000 − 30,000 − 6,000 − 10,000 = 54,000원`, 회수 `ceil(10,000/3,200) = 4개`. 미판매 10개의 15,000원을 다시 빼면 실패로 친다.

**현금과 원가는 다른 값이다.** 필요 600g·보유 200g·500g 포장 10,000원·단가 20원/g이면 구매는 1포장 10,000원(현금), 600g 소비 원가는 12,000원, 잔여 원재료는 100g이다. 사전 현금 필요액 = 추가 재료 구매액 + 추가 포장재 구매액 + L + F이고, 판매 후 차감되는 수수료는 별도로 표시해 사전 현금에 중복 포함하지 않는다. 화면은 (1) 사전 현금 (2) 사용 원가 (3) 판매량별 손익 (4) 잔여 원재료·포장재 (5) 선제조 미판매분에 이미 포함된 손실을 각각 다른 줄로 보여 준다.

**보유 재고를 공짜로 치지 않는다.** 원가 단가는 보유분과 신규 구매분의 가중평균이 기본이다. 보유분 단가를 모르면 사용자에게 가정 승인·입력을 받고, 보유량이 있다는 이유로 단가를 0으로 처리하지 않는다. 사용할 수 없는 재고나 유통 상태가 확인되지 않은 재고는 사용 가능 보유량에 자동으로 넣지 않는다. 구매는 포장 단위이므로 `ceil(추가필요량 / 구매포장량)`으로 올림한다.

**포장비는 시점을 고른다.** 제조할 때 전량 포장하면 그 비용은 `Q × c` 쪽으로 옮기고 판매 시 포장비 `b`에 다시 넣지 않는다. UI에서 `at_preparation` / `at_sale`을 선택하면 계산 필드가 자동으로 갈린다.

**0과 null을 구분한다.** `0`을 쓰려면 "발생하지 않음"이 확인돼야 하고 불명확하면 null이다. 누락값이 필수 비용에 영향을 주면 총액을 확정하지 않는다. 임의의 중앙값으로 확정 금액을 만들지 않고 범위는 시나리오로만 제공한다. 분모가 0 이하면 '판매로 비용 회수 불가', 필요 수량이 Q를 초과하면 '이번 준비 수량 내 회수 불가', 고정비가 0이면 회수 수량 0의 의미를 따로 설명해 흑자 전환 최소 수량과 혼동시키지 않는다.

**계산 범위를 좁혀서 적는다.** 이 계산기는 신메뉴 시험에 직접 관련된 추가 비용만 비교하며 가게 전체의 회계상 순이익이나 세금 신고용이 아니다. 임대료·감가상각·기존 상시 인건비는 포함하지 않았다는 사실 자체를 화면에 표시한다. 재사용 장비 감가상각은 P1로 미뤘다.

**AI를 부르지 않는다.** 판매 수량 슬라이더(0~Q, 기본 25/50/75/100%)를 움직이면 코드 계산만 즉시 갱신하고 AI를 재호출하지 않는다. 기본 시나리오는 가정이지 예상 수요가 아니라고 표시한다. AI 배합은 시험 조리 초안이므로 사장님이 투입량·완성 수량을 확인하기 전에는 '가정 배합 기준'으로 표시하고, 손질·조리 손실은 완성 수량에만 반영해 투입량과 완성 수량에 같은 손실률을 중복 적용하지 않는다.
