## 1. 한 줄 정의

LLM 비전 호출을 기본값 모델 → 대체 모델 목록 → 휴리스틱의 3단 폴백으로 감싸서, 권한 문제(404/403)나 키 부재로도 데모가 멈추지 않게 하는 구성.

## 2. 어디서 썼는가

- [[wanted-hackathon-2026]] — 사진 속 물체의 소재(나무/금속/유리) 판단. 서버는 `serve.js`의 `POST /api/analyze`, 클라이언트 쪽 판단 로직과 휴리스틱은 `src/photo/material.js`.

## 3. 실제로 겪은 문제와 해결

**모델 권한을 미리 알 수 없다.** 기본값을 그 시점 최신 플래그십으로 두되, 계정에 권한이 없으면(404/403) 환경변수의 대체 목록을 순서대로 시도한다.

```
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-6-astra
OPENAI_MODEL_FALLBACKS=gpt-5.6-sol,gpt-5.6-terra
```

어떤 모델이 실제로 답했는지는 서버 로그에 남긴다. `.env`와 터미널 환경변수를 모두 지원하고, 둘 다 있으면 터미널 값이 우선이다.

> 주의: 원자료 안에서 모델명이 갈린다. 설정 절은 `gpt-6-astra`, 파이프라인 다이어그램은 `gpt-5-mini`. 자세한 내용은 [[wanted-hackathon-2026]] 상단의 모순 블록.

**LLM이 아예 없는 경우까지 대비.** 키가 없거나 호출이 실패하면 색상 통계 기반 간이 판단(`heuristicMaterial` 점수식)으로 자동 폴백한다. 사용자에게는 힌트 문구로 "간이 판단" / "OpenAI" 중 어느 경로였는지 보여준다. 폴백을 숨기지 않고 표시한 점이 데모 신뢰에 중요했다.

**출력 안정화와 비용.** 이미지는 `detail: low`로 보내고 응답은 JSON 스키마로 고정한다. `gpt-6-astra` 기준 입력 $10 / 출력 $50 per 1M 토큰, 사진 한 장당 약 10원 안팎. 더 아끼려면 경량 모델(`gpt-5.6-luna`)로 바꾼다.

**출력 범주를 좁히기.** 모델이 내놓는 임의의 소재명을 세 가지로 접는 규칙(도자기→유리, 플라스틱→금속 등)을 `serve.js`의 `INSTRUCTIONS`에 둔다. 렌더러가 다룰 수 있는 범주가 3개뿐이므로 매핑을 프롬프트 쪽에서 강제한 것이다.

**검증 공백.** 작업 PC에 키가 없어 **실제 응답 경로는 미검증**이고 키 없을 때의 503 폴백만 확인됐다. 단건 확인용 CLI로 `node tools/analyze.js samples/mug.jpg`가 준비돼 있다. 폴백이 너무 잘 동작하면 주 경로가 죽은 것을 모른 채 지나갈 수 있다는 점이 위험이다.

## 학습

### CS 주제
- 네트워크: HTTP 상태 코드로 실패 원인 구분(404/403 권한, 503 비가용)
- 분산시스템: 폴백과 우아한 성능 저하(graceful degradation), 실패 시 대체 값
- 소프트웨어공학: 환경변수 기반 설정 우선순위, 관측 가능성(어떤 경로로 답했는지 로깅)

### 설명할 수 있어야 하는 것
- 계정에 어떤 모델 권한이 있는지 미리 알 수 없고 데모 중에 멈추면 안 돼서 기본 모델과 대체 모델 목록과 비LLM 휴리스틱 3단으로 감싼 이유를 설명할 수 있습니다.
- 모델 하나에 고정하면 구성은 단순하지만 권한이 없을 때 기능이 통째로 죽는다는 점과, 폴백을 붙인 대가로 지금 어느 경로인지를 사용자와 로그 양쪽에 드러내야 했던 사정을 말할 수 있습니다.
- 폴백이 너무 잘 동작하면 주 경로가 죽은 것을 모른 채 지나간다는 점과, 실제로 이 프로젝트의 응답 경로가 미검증으로 남았다는 점을 설명할 수 있습니다.

### 확인 질문
1. **Q:** (L1 개념) 폴백 체인이 무엇이고, 이 구현에서 3단은 각각 무엇이었나요?
   **A:** 실패했을 때 다음 대안으로 내려가며 기능을 유지하는 방식입니다. 여기서는 기본값을 그 시점 최신 플래그십으로 두고, 계정에 권한이 없어 404나 403이 오면 `OPENAI_MODEL_FALLBACKS`에 적힌 대체 모델을 순서대로 시도하며, 키가 없거나 호출이 실패하면 색상 통계 기반 간이 판단인 `heuristicMaterial` 점수식으로 내려갑니다. 마지막 단이 LLM 없이도 동작한다는 점이 중요했고, 어떤 모델이 실제로 답했는지는 서버 로그에 남겼습니다.
   **꼬리:** 그러면 404나 403 같은 권한 실패와 일시적 네트워크 실패를 같은 정책으로 처리해도 되나요?
   **틀리기 쉬운 답:** "모델 목록을 돌리는 것도 재시도입니다"라고 답하는 경우가 있는데, 같은 대상에 다시 거는 재시도와 다른 대상으로 내려가는 폴백은 다르고 권한 실패는 재시도해도 회복되지 않습니다.
2. **Q:** (L2 판단) 폴백으로 내려갔다는 사실을 사용자에게 숨기지 않고 표시하신 이유가 있나요?
   **A:** 사용자에게 힌트 문구로 간이 판단인지 OpenAI인지 어느 경로였는지 보여 줬습니다. 간이 판단은 색상 통계에 기댄 근사라서 같은 화면에 같은 확신으로 표시하면 결과의 신뢰도를 오해하게 된다고 봤습니다. 원자료에도 폴백을 숨기지 않고 표시한 점이 데모 신뢰에 중요했다고 적어 뒀습니다.
   **꼬리:** 그러면 사용자에게 보이는 표시 말고, 운영자가 폴백 비율을 알아채려면 무엇이 필요할까요?
   **틀리기 쉬운 답:** "사용자 경험을 위해 폴백은 티 안 나게 숨기는 게 낫습니다"라고 답하는 경우가 있는데, 품질이 다른 경로를 같은 것처럼 보이게 하면 신뢰가 더 크게 깨집니다.
3. **Q:** (L2 판단) 모델 출력 범주를 나무와 금속과 유리 셋으로 접는 규칙을 프롬프트 쪽 `INSTRUCTIONS`에 두신 이유는 무엇이고, 비용은 어떻게 통제하셨나요?
   **A:** 렌더러가 다룰 수 있는 범주가 3개뿐이라 도자기는 유리로, 플라스틱은 금속으로 가는 매핑을 프롬프트에서 강제했습니다. 출력 안정화는 JSON 스키마 고정으로 했고, 비용은 이미지를 `detail: low`로 보내 통제했습니다. `gpt-6-astra` 기준으로 입력 $10, 출력 $50 per 1M 토큰이라 사진 한 장당 10원 안팎이었고, 더 아끼려면 경량 모델인 `gpt-5.6-luna`로 바꾸면 됩니다.
   **꼬리:** 그러면 매핑을 프롬프트가 아니라 서버 코드에 두면 무엇이 달라지나요?
   **틀리기 쉬운 답:** "스키마로 enum을 강제했으니 매핑은 필요 없습니다"라고 답하는 경우가 있는데, 모델이 임의의 소재명을 내놓는 문제와 렌더러 범주를 맞추는 문제는 별개이고 이 구현은 프롬프트에서 접는 쪽을 골랐습니다.
4. **Q:** (L3 한계) 이 구성에서 가장 위험한 실패는 무엇이라고 보시나요?
   **A:** 폴백이 너무 잘 동작해서 주 경로가 죽은 것을 모른 채 지나가는 경우라고 생각합니다. 실제로 작업 PC에 키가 없어서 실제 응답 경로는 미검증이고 키가 없을 때의 503 폴백만 확인된 상태로 남았습니다. 단건 확인용 CLI인 `node tools/analyze.js samples/mug.jpg`가 준비돼 있으니 키를 넣고 주 경로를 한 번 통과시키는 것이 남은 일입니다. 원자료 안에서 모델명도 갈려 있어서(설정 절은 `gpt-6-astra`, 파이프라인 다이어그램은 `gpt-5-mini`) 실제로 무엇이 불렸는지도 확정하지 못했습니다.
   **꼬리:** 그러면 주 경로가 죽은 것을 일찍 알리려면 어떤 경보 조건을 거시겠어요?
   **틀리기 쉬운 답:** "폴백이 있으니 장애가 나도 문제없습니다"라고 답하는 경우가 있는데, 폴백은 장애를 감추는 장치이기도 해서 감지 수단을 따로 둬야 합니다.
