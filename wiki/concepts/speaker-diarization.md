## 1. 한 줄 정의

음성을 텍스트로 옮기면서(전사) 동시에 "누가 말했는가"로 발언을 나누는 것. 대화형 영상에서는 전사만으로는 부족하고, 발언 주체가 붙어야 근거로 쓸 수 있다.

## 2. 어디서 썼는가

- [[wanted-interview-ai-2026]] — FRAME. AssemblyAI(`universal-2` 기본값)로 한국어 전사와 화자 구분을 수행한다.

## 3. 실제로 겪은 문제와 해결

녹화 면접 영상에는 면접관과 지원자의 말이 섞여 있다. 전사문만 있으면 "협업 경험을 말해달라"는 질문과 그에 대한 답변이 구분되지 않아, 기준별 근거를 뽑을 때 면접관의 말이 지원자의 근거로 잡힐 수 있다.

FRAME의 처리 방식은 **자동 화자 구분 + 사람의 역할 지정**의 2단계다. AssemblyAI가 화자를 분리해 주면, 사용자가 전사된 발언을 보고 어느 화자가 지원자이고 어느 쪽이 면접관인지 직접 지정한다. 화자 지정이 끝나야 근거 분석 단계로 넘어간다. 즉 모델은 "화자 A/B"까지만 책임지고, "A가 지원자"라는 역할 매핑은 사람이 확정한다. 이렇게 확정된 역할이 [[evidence-linked-llm-output]]의 전제가 된다.

운영상 기록된 것:

- 전사는 [[background-job-pipeline]]의 백그라운드 작업으로 돌린다. 영상 업로드 후 전사 완료 → 화자 지정 → 분석이라는 순서가 강제된다.
- 전사 모델은 `ASSEMBLYAI_MODEL` 환경변수로 바꿀 수 있지만, 바꿀 때 **한국어 전사와 화자 구분을 지원하는지** 확인해야 한다고 문서에 못박아 두었다.
- 전사를 위해 영상 자체가 AssemblyAI로 전달된다. 삭제 요청 시 저장된 영상뿐 아니라 **외부 전사도 함께 삭제**하고, 실패하면 정리 작업에서 재시도한다.
- 입력은 한국어 MP4 최대 50MB·15분으로 제한했다.

### CS 주제
- 머신러닝: 화자 구분(발화 구간 군집화)과 전사 모델, 라벨과 신원의 구분
- 소프트웨어공학: 자동 결과에 사람 확정 단계를 끼워 넣는 파이프라인 설계
- 보안: 원본 미디어가 외부 제공자로 나가는 경로와 삭제 보장

### 설명할 수 있어야 하는 것
- AssemblyAI가 화자 A/B 라벨까지만 내놓게 하고 A가 지원자라는 역할 매핑은 사람이 확정하도록 2단계로 나눈 이유와, 그 확정이 근거 분석보다 먼저 와야 하는 순서를 설명할 수 있습니다.
- 역할 매핑을 LLM 자동 추정으로 대신했다면 단계 하나를 없앨 수 있었지만 면접관 발언이 지원자 근거로 잡히는 오염과 사람의 최종 판단 원칙을 잃는다는 점을 말할 수 있습니다.
- 전사 모델을 `ASSEMBLYAI_MODEL`로 바꿀 때 한국어 전사·화자 구분·구조화된 응답 지원을 먼저 확인해야 하는 이유와, 영상이 AssemblyAI로 나가는 이상 삭제가 외부 전사까지 닿아야 하고 앱 보관 기간과 제공자 정책이 별개라는 점을 설명할 수 있습니다.

### 확인 질문
1. **Q:** (L1 개념) 전사와 화자 구분은 어떻게 다르고, 화자 구분이 실제로 내놓는 것은 무엇인지 설명해 주시겠어요?
   **A:** 전사는 음성을 텍스트로 옮기는 일이고 화자 구분은 언제부터 언제까지를 누가 말했는지로 발언을 나누는 일입니다. 화자 구분이 주는 것은 신원이 아니라 라벨뿐이라는 점이 중요하다고 생각합니다. FRAME에서 AssemblyAI는 기본값 `universal-2`로 화자 A와 B까지만 책임지고, 어느 쪽이 지원자이고 어느 쪽이 면접관인지는 사용자가 전사된 발언을 보고 직접 지정하게 했습니다.
   **꼬리:** 그러면 화자 수를 미리 알려 주면 정확도는 어떻게 되고, 잘못 알려 주면 어떻게 되나요?
   **틀리기 쉬운 답:** "diarization이 화자의 이름이나 역할까지 알아냅니다"라고 답하는 경우가 있는데, 실제로 모델이 내놓는 것은 A나 B 같은 익명 라벨입니다.
2. **Q:** (L2 판단) 역할 매핑을 자동화하지 않고 사람이 확정하게 하신 이유는 무엇인가요?
   **A:** 녹화 면접 영상에는 면접관과 지원자의 말이 섞여 있는데, 전사문만 있으면 협업 경험을 말해 달라는 질문과 그에 대한 답변이 구분되지 않아서 기준별 근거를 뽑을 때 면접관의 말이 지원자의 근거로 잡힐 수 있었습니다. 그래서 자동 화자 구분에 사람의 역할 지정을 붙인 2단계를 두고, 화자 지정이 끝나야 근거 분석으로 넘어가도록 순서를 강제했습니다. 이렇게 확정된 역할이 [[evidence-linked-llm-output]]의 전제가 됩니다.
   **꼬리:** 그러면 사용자가 역할을 반대로 지정하면 뒤따르는 분석 결과는 어떻게 되나요?
   **틀리기 쉬운 답:** "질문과 답변 말투를 보고 LLM이 역할을 붙이면 사람 단계는 없앨 수 있습니다"라고 답하는 경우가 있는데, 실제로는 서비스 원칙이 사람의 최종 판단이고 역할을 잘못 배정하면 근거 전체가 오염돼서 자동 추정으로 되돌리기 어렵습니다.
3. **Q:** (L2 판단) 전사를 요청 안에서 처리하지 않고 백그라운드 작업으로 빼신 이유가 있나요?
   **A:** 영상 전사와 뒤따르는 LLM 분석이 수 분까지 걸릴 수 있어서 서버리스 HTTP 요청 수명 안에서 끝나지 않았습니다. 그래서 업로드 직후에는 Supabase 비공개 버킷에 저장만 하고, 전사는 [[background-job-pipeline]]의 Trigger.dev 작업으로 돌리게 했습니다. 그렇게 하니 영상 업로드, 전사 완료, 화자 지정, 분석이라는 순서가 저절로 강제됐습니다.
   **꼬리:** 그러면 전사 작업이 중간에 실패하면 사용자 화면에는 무엇이 남고, 재시도는 누가 걸게 되나요?
   **틀리기 쉬운 답:** "업로드 응답에서 바로 전사 결과를 돌려주면 흐름이 단순해집니다"라고 답하는 경우가 있는데, 실제로는 그 응답을 기다리는 동안 함수 수명이 먼저 끝납니다.
4. **Q:** (L3 한계) 전사 모델을 바꾸려면 무엇부터 확인해야 하고, 원본이 외부로 나가는 문제는 어떻게 처리하셨나요?
   **A:** 모델은 `ASSEMBLYAI_MODEL` 환경변수로 바꿀 수 있지만, 한국어 전사와 화자 구분과 구조화된 응답을 지원하는지 먼저 확인하라고 문서에 못박아 뒀습니다. 셋 중 하나만 빠져도 뒷단이 조용히 망가지기 때문입니다. 데이터 쪽으로는 전사를 위해 영상 자체가 AssemblyAI로 전달되므로 삭제 요청이 오면 저장된 영상뿐 아니라 외부 전사도 함께 삭제하고, 실패하면 정리 작업에서 다시 시도하게 했습니다. 입력은 한국어 MP4 최대 50MB에 15분으로 제한했습니다.
   **꼬리:** 그러면 앱의 24시간 보관 정책과 외부 제공자의 데이터 처리 정책은 같은 것인가요?
   **틀리기 쉬운 답:** "우리 스토리지에서 지웠으니 데이터는 다 지워졌습니다"라고 답하는 경우가 있는데, 실제로는 외부 전사본이 남고 앱의 보관 기간과 제공자 정책은 문서에서 별개로 구분하고 있습니다.
