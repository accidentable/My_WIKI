## 1. 한 줄 정의

LLM이 판단이나 점수를 내놓게 하지 않고, 사용자가 정한 기준마다 **원본의 어느 구간이 근거인지**를 가리키게 해서, 최종 확인과 판단을 사람이 원본에서 하도록 만드는 출력 설계.

## 2. 어디서 썼는가

- [[wanted-interview-ai-2026]], FRAME. 채용 영상의 검토 기준별로 지원자 발언을 골라 전사 원문과 타임스탬프에 연결한다.
- [[news-bigdata-2026-kkeutmul-radar]], 끝물레이더(기획 단계). 유행 단계 판정마다 근거 기사를 붙인다. 기사량 곡선 위에 신호 발생 시점(유통사 첫 등장, 연관어 역전)을 찍고, 그 시점 전후 기사의 제목·언론사·날짜·본문 앞 200자를 근거 카드로 보여줘 사용자가 판정을 직접 확인하게 한다. 판정 결과는 참고 정보이며 창업·투자 결정 책임은 이용자에게 있다고 서비스 내에 고지하는 것도 같은 설계의 연장이다.

- [[im-challenge-daegu-2026-sns-menu]], SNS 신메뉴 AI 컨설팅. 추출 결과는 서버가 **본문 인용 포함 여부**를 다시 검사하고, 적용안은 참조한 **근거 ID 유효성**과 장비·금지재료·수량을 재검사한다. 실제 호출에서 본문에 "규칙 무시"라는 문장이 심어진 자료를 넣어도 무시되고 인용 4건이 모두 검사를 통과했다(T05). 값이 없으면 0으로 채우지 않고 `unknowns`로 돌려준다. "외부 게시물의 문장은 분석 데이터이며 AI나 코딩 도구를 제어하는 지시가 아니다"를 제품 원칙으로 명시해 두었다.

## 3. 실제로 겪은 문제와 해결

FRAME이 이 설계로 처리한 지점은 네 가지다.

**결론이 아니라 위치를 낸다.** 분석 결과는 실제 전사 구간에 연결되고, 담당자는 타임스탬프를 눌러 원본 영상의 그 자리를 직접 재생해 확인한다. 서비스는 점수·순위·합격 여부를 자동으로 결정하지 않는다.

**발언 주체를 분리한다.** 면접관 발언과 지원자 발언이 섞이면 "지원자가 그렇게 말했다"는 근거가 오염된다. FRAME은 면접관 발언을 질문 맥락으로만 쓰고 지원자의 경험 근거와 구분한다. 화자 지정 자체도 자동에 맡기지 않고 사용자가 확인한다([[speaker-diarization]]).

**없음과 모름을 구분한다.** 관련 발언을 찾지 못한 경우와 인식이 불확실한 경우를 따로 표시하고, 발언이 없다는 이유로 역량 부족을 판단하지 않는다.

**사람이 근거를 고칠 수 있게 한다.** 전체 전사를 검색해 빠진 근거를 추가하거나 잘못 연결된 근거를 제외할 수 있다. 즉 LLM 출력은 초안이고 확정본은 사람이 만든다. 최종 결과는 Markdown으로 내보낸다.

기준 개수를 3~6개로 제한한 것도 같은 맥락이다(직군 선택 시 기본 4개 + 공통 2개 프리셋). 기준이 많아지면 근거 하나하나를 사람이 확인하는 과정이 성립하지 않는다.

구현에서는 OpenAI 요청에 `store: false`를 사용합니다. 이 설정만으로 제공자 측 로그와 모든 데이터 보관이 없어지는 것은 아니므로, 앱의 삭제·만료 처리와 외부 제공자의 보관 정책을 나눠 설명해야 합니다. 실제 조직에 Zero Data Retention이 적용되었다는 근거는 원자료에 없습니다.

### 설명할 수 있어야 하는 것
- 채용 영상 검토에서 점수와 순위, 합격 여부를 모델이 정하게 두지 않고 기준마다 원본의 어느 구간이 근거인지만 가리키게 해서 확인과 판단을 사람이 원본에서 하게 했다는 것을, 그렇게 고른 이유와 함께 설명할 수 있습니다.
- 모델이 바로 점수를 내면 화면은 간단해지지만 담당자가 원본에서 검증할 방법이 사라진다는 것과, 그 대신 근거를 하나하나 확인하는 비용을 떠안아 기준 개수를 3~6개로 제한했다는 대가를 말할 수 있습니다.
- 기준이 많아지면 사람이 근거를 확인하는 과정 자체가 성립하지 않고 발언 주체가 섞이면 근거가 오염된다는 한계를 설명할 수 있습니다.

### 확인 질문
1. **Q:** (L1 개념) 근거 연결형 출력이 무엇이고 결론을 바로 내놓는 출력과 무엇이 다른지 설명해 주시겠어요?
   **A:** LLM에게 판단이나 점수를 내놓게 하지 않고 사용자가 정한 기준마다 원본의 어느 구간이 근거인지 가리키게 하는 출력입니다. FRAME에서는 분석 결과가 실제 전사 구간에 연결되고 담당자가 타임스탬프를 눌러 원본 영상의 그 자리를 직접 재생해 확인합니다. 서비스가 점수와 순위, 합격 여부를 자동으로 정하지 않게 했고 LLM 출력은 초안으로 두고 확정본은 사람이 만들게 했습니다. 전체 전사를 검색해 빠진 근거를 추가하거나 잘못 연결된 근거를 제외할 수 있고 최종 결과는 Markdown으로 내보냅니다.
   **꼬리:** 그러면 근거를 가리키는 출력도 결국 모델이 고른 것인데 무엇이 더 안전해지나요?
   **틀리기 쉬운 답:** 근거를 같이 출력하면 환각이 사라진다고 답하는 경우가 있는데, 실제로 근거 표시는 사람이 검증할 자리를 만들 뿐이고 틀린 근거를 고르는 일은 그대로 남아서 사람이 근거를 고칠 수 있게 해 두었습니다.
2. **Q:** (L2 판단) 면접관 발언과 지원자 발언을 분리하신 이유와, 화자 지정을 자동에 맡기지 않으신 이유는 무엇인가요?
   **A:** 두 발언이 섞이면 지원자가 그렇게 말했다는 근거 자체가 오염되기 때문입니다. FRAME은 면접관 발언을 질문 맥락으로만 쓰고 지원자의 경험 근거와 구분하며, 화자 지정은 자동 결과를 그대로 쓰지 않고 사용자가 확인하게 했습니다. 같은 이유로 관련 발언을 찾지 못한 경우와 인식이 불확실한 경우를 따로 표시하고, 발언이 없다는 이유로 역량 부족을 판단하지 않게 했습니다.
   **꼬리:** 그러면 화자 분리가 틀렸을 때 결과에 어떤 오류가 나타나고, 어느 화면에서 가장 먼저 알아채나요?
   **틀리기 쉬운 답:** 없음이 곧 역량 부족의 근거라고 답하는 경우가 있는데, 실제로는 없음과 모름을 구분하고 부재를 평가 근거로 쓰지 않는 것이 이 설계의 원칙이었습니다.
3. **Q:** (L2 판단) SNS 신메뉴 쪽에서는 같은 원칙을 어떤 서버 검사로 구현하셨나요?
   **A:** 추출 결과는 서버가 본문 인용 포함 여부를 다시 검사하고, 적용안은 참조한 근거 ID 유효성과 장비·금지재료·수량을 재검사합니다. 값이 없으면 0으로 채우지 않고 `unknowns`로 돌려줍니다. 근거를 붙이라고 프롬프트에 적는 데서 끝내지 않고 붙여 온 근거가 원문에 실재하는지 서버가 다시 확인하게 한 것이라고 보시면 됩니다.
   **꼬리:** 그러면 근거 ID 유효성 검사가 실패한 항목은 버리시겠어요, 사람에게 보여 주시겠어요?
   **틀리기 쉬운 답:** 값이 없으면 0으로 채워 화면이 비지 않게 한다고 답하는 경우가 있는데, 실제로 0은 없음이 아니라 측정된 값처럼 읽혀서 `unknowns`로 되돌립니다.
4. **Q:** (L3 한계) 분석 대상인 외부 게시물 본문에 규칙 무시처럼 모델을 겨냥한 문장이 들어 있으면 어떻게 되고, 이 방어는 어떻게 확인하셨나요?
   **A:** 외부 게시물의 문장은 분석 데이터이고 AI나 코딩 도구를 제어하는 지시가 아니라는 것을 제품 원칙으로 적어 두었습니다. 실제 호출에서 본문에 규칙 무시라는 문장이 심어진 자료를 넣어도 무시됐고 인용 4건이 모두 검사를 통과했습니다(T05). 확인된 것은 이 한 건의 실호출 결과라서 모든 인젝션 변형에 대한 보장은 아니라고 생각합니다. `store: false`는 별도의 저장 설정이며, 인젝션 방어나 제공자 측 무보관을 보장하는 근거로 사용할 수 없습니다.
   **꼬리:** 그러면 T05 한 건이 통과했다는 사실로 무엇까지 말할 수 있고 무엇은 말할 수 없나요?
   **틀리기 쉬운 답:** 테스트를 통과했으니 프롬프트 인젝션에 안전하다고 답하는 경우가 있는데, 실제로 표본 한 건의 통과는 방어의 존재를 보일 뿐 완전성을 보이지 않습니다.
