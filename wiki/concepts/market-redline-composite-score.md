# 레드라인 근접도 합산 점수

## 1. 한 줄 정의

%, 포인트, 달러처럼 단위와 스케일이 다른 지표들을 하나의 숫자로 합치기 위해, 지표마다 "여기까지는 아무 일 없음"인 **safe**와 "여기 닿으면 만점"인 **redline** 두 값을 사람이 정하고, 그 사이를 선형 보간해 0~1점으로 바꾼 뒤 단순 합산하는 방식.

## 2. 어디서 썼는가

- [[taco-index-2026-03]]: TACO Index. S&P 선물 고점대비 하락률, VIX, 10년물 금리, WTI, 달러인덱스, 지지율 6개를 각각 0~1점으로 바꿔 만점 6.0으로 합산하고, 1.8 / 3.0 / 4.2를 경계로 레벨 1~4를 붙였다.

## 3. 어떻게 계산하나

방향(`direction`)이 `above`면 값이 클수록 위험, `below`면 작을수록 위험이다.

```python
if direction == "above":
    if value <= safe: return 0.0
    if value >= redline: return 1.0
    return (value - safe) / (redline - safe)
else:
    if value >= safe: return 0.0
    if value <= redline: return 1.0
    return (safe - value) / (safe - redline)
```

`below`는 safe > redline이므로 분모가 양수로 유지된다. 음수 구간(S&P 하락률 safe=-3, redline=-15)에서도 같은 식이 그대로 성립한다. TACO Index의 `api/_shared.py`는 `rl < 0`인 경우를 따로 분기해 두었지만 두 분기의 계산식이 동일해 실제로는 불필요하다.

## 4. 왜 이렇게 하나 (장점)

- **정규화 기준을 데이터가 아니라 도메인이 정한다.** min-max나 z-score는 관측 구간에 따라 기준이 흔들리지만, safe/redline은 "VIX 35면 패닉"처럼 고정된 의미를 가진다. 과거 데이터가 없어도, 데이터 분포가 바뀌어도 점수의 뜻이 유지된다.
- **부분 점수가 자연스럽다.** 임계값을 넘었나/아닌가의 0-1 판정이 아니라, 레드라인에 얼마나 가까운지가 연속적으로 반영돼 총점이 부드럽게 움직인다. 대시보드처럼 매 시각 값이 바뀌는 화면에 맞는다.
- **지표를 빼거나 더하기 쉽다.** 각 항이 독립적으로 0~1이므로 지표 수 = 만점이고, 가중치 논쟁 없이 항목만 추가하면 된다. TACO Index도 커밋 도중 VIX를 추가하며 만점을 5에서 6으로 올렸다.
- **한 항목만 봐도 설명이 된다.** UI에서 지표 카드마다 자기 점수와 레드라인 값을 같이 보여줄 수 있다.

## 5. 실제로 겪은 문제

- **safe/redline 값의 근거가 남지 않는다.** TACO Index 코드에는 VIX 35, 10년물 4.5, 유가 100 같은 숫자만 있고 왜 그 값인지 설명이 없다. 이 방식은 임계값에 결과가 통째로 좌우되므로, 값 옆에 근거(역사적 분위, 참고 기사, 정한 날짜)를 주석으로 남기지 않으면 나중에 아무도 손댈 수 없다.
- **주석과 상수가 어긋난다.** 같은 파일에 `# S&P 500: safe=-5, redline=-20`이라 적혀 있는데 실제 상수는 `-3.0 / -15.0`이었다. 임계값 튜닝은 잦으므로 주석에 숫자를 복사해 두면 반드시 썩는다. 상수 딕셔너리 하나만 진실로 두는 편이 낫다.
- **항목을 하나 빠뜨려도 티가 안 난다.** TACO Index의 `backend/` 쪽은 6개 중 지지율을 빼고 5개만 합산하면서 레벨 경계는 만점 6.0 기준을 그대로 써서, 구조적으로 점수가 낮게 나왔다. 합산 항목 수와 만점을 같은 곳에서 유도하지 않으면 생기는 사고다.
- **단순 합산은 곧 균등 가중이다.** 지지율 1점과 VIX 1점이 같은 무게를 가진다. 자료에는 이 선택에 대한 검토 흔적이 없다(추정: 의도적 단순화).
- **과거 시계열이 없는 지표를 섞으면 히스토리가 오염된다.** 지지율은 일별 과거값을 못 구해 현재값을 전 구간에 채워 넣었고, 그 결과 과거 총점이 오늘의 지지율을 가정한 값이 됐다. 히스토리 차트를 그릴 거라면 "모든 지표에 과거 시계열이 있는가"를 지표 선정 단계에서 먼저 확인해야 한다.

## 6. 참고 자료

- `tacotrump/backend/app/services/score_engine.py`: REDLINES 상수와 레벨 경계
- `tacotrump/api/_shared.py`: 배포판 구현, `calc_indicator_score` / `calc_total` / `get_risk`

- 대안은 무엇이었고 무엇을 포기했는가 (임계값 0-1 판정 / 부드러운 총점을 얻고 임계값 근거 부담을 떠안음)

### 확인 질문
1. **Q:** (L1 개념) 단위가 다른 지표를 하나로 합칠 때 흔히 쓰는 정규화는 무엇이 있고, 이 프로젝트는 왜 그것들을 쓰지 않았는가?
   **A:** 일반적인 선택지는 min-max 재척도와 z-score 표준화다. 둘 다 정규화 기준을 관측 데이터에서 가져오므로 관측 구간이 바뀌면 같은 값의 점수가 달라진다. TACO Index는 대신 지표마다 "여기까지는 아무 일 없음"인 safe와 "여기 닿으면 만점"인 redline을 사람이 정하고 그 사이를 선형 보간해 0~1로 바꿨다. "VIX 35면 패닉"처럼 고정된 의미를 갖기 때문에 과거 데이터가 없어도, 분포가 바뀌어도 점수의 뜻이 유지된다는 것이 선택 이유다.
   **꼬리:** 데이터 기반 정규화가 오히려 나은 상황은 어떤 경우인가?
   **틀리기 쉬운 답:** "min-max도 0~1이니 결국 같다" — min/max가 관측 구간에 따라 움직이면 같은 VIX 값이 어제와 오늘 다른 점수를 받는다.

2. **Q:** (L2 판단) `direction`이 `below`인 지표와 음수 구간 지표를 같은 식으로 처리할 수 있는 이유는?
   **A:** `above`면 값이 클수록 위험, `below`면 작을수록 위험이고, `below`는 safe > redline이므로 `(safe - value) / (safe - redline)`의 분모가 양수로 유지된다. 음수 구간(S&P 하락률 safe=-3, redline=-15)에서도 같은 식이 그대로 성립한다. 실제로 `api/_shared.py`는 `rl < 0`인 경우를 따로 분기해 뒀지만 두 분기의 계산식이 동일해 불필요한 분기다. 각 항이 독립적으로 0~1이라 지표 수 = 만점이 되고, 가중치 논쟁 없이 항목만 더하면 되므로 실제로 커밋 도중 VIX를 추가하며 만점을 5에서 6으로 올릴 수 있었다.
   **꼬리:** 항목을 더하기 쉬운 구조는 어떤 위험을 같이 들여오는가?
   **틀리기 쉬운 답:** "음수 지표는 부호를 뒤집어 따로 처리해야 한다" — safe/redline의 대소 관계가 방향을 이미 담고 있다.

3. **Q:** (L2 판단) 단순 합산을 택한 것은 어떤 가중치 결정과 같은가? 이 프로젝트는 그것을 검토했는가?
   **A:** 단순 합산은 균등 가중과 같다. 지지율 1점과 VIX 1점이 총점에 똑같은 무게를 가진다는 뜻이다. 자료에는 이 선택에 대한 검토 흔적이 없고, 문서는 이를 의도적 단순화로 추정해 두었다. 총점 6.0 만점에 1.8 / 3.0 / 4.2를 경계로 레벨 1~4를 붙이는 구조라, 가중치를 바꾸면 레벨 경계도 함께 다시 정해야 한다.
   **꼬리:** 가중치를 넣는다면 그 값의 근거를 어디서 가져오겠는가?
   **틀리기 쉬운 답:** "가중치를 안 줬으니 중립적이다" — 균등 가중도 하나의 선택이고, 지표를 하나 더 넣는 순간 기존 지표의 상대 비중이 줄어든다.

4. **Q:** (L3 한계) 이 방식에서 실제로 사고가 난 지점을 셋 들고, 각각의 재발 방지책을 말하라.
   **A:** 첫째, 주석과 상수가 어긋났다 — 같은 파일에 `# S&P 500: safe=-5, redline=-20`이라 적혀 있는데 실제 상수는 `-3.0 / -15.0`이었다. 임계값 튜닝이 잦으므로 상수 딕셔너리 하나만 진실로 두는 편이 낫다. 둘째, `backend/` 쪽이 6개 중 지지율을 빼고 5개만 합산하면서 레벨 경계는 만점 6.0 기준을 그대로 써서 구조적으로 점수가 낮게 나왔다. 합산 항목 수와 만점을 같은 곳에서 유도하면 막을 수 있다. 셋째, safe/redline 값의 근거가 코드에 남아 있지 않다 — VIX 35, 10년물 4.5, 유가 100 같은 숫자만 있고 왜 그 값인지 설명이 없어, 값 옆에 역사적 분위·참고 기사·정한 날짜를 주석으로 남기지 않으면 나중에 아무도 손댈 수 없다.
   **꼬리:** 임계값에 결과가 통째로 좌우되는 지수라면, 배포 전에 무엇을 한 번 돌려 보겠는가?
   **틀리기 쉬운 답:** "테스트가 통과했으니 두 구현이 같다" — 만점 상수가 다른 두 구현은 각자 일관되게 틀린 값을 낼 수 있다.

5. **Q:** (L3 한계) 이 점수로 과거 히스토리 차트를 그리려 할 때 무엇이 먼저 깨졌는가?
   **A:** 과거 시계열이 없는 지표다. 지지율은 일별 과거값을 구하지 못해 현재값을 전 구간에 채워 넣었고, 그 결과 과거 총점이 오늘의 지지율을 가정한 값이 됐다. 히스토리를 그릴 계획이라면 "모든 지표에 과거 시계열이 있는가"를 지표 선정 단계에서 먼저 확인해야 한다는 교훈이다. 지금 구조는 실시간 대시보드에는 맞지만 과거 비교에는 그대로 쓸 수 없다.
   **꼬리:** 과거값이 없는 지표를 히스토리에서 빼면 총점의 해석은 어떻게 되는가?
   **틀리기 쉬운 답:** "빈 값은 최신값으로 채우면 된다" — 그 순간 과거 점수는 관측이 아니라 오늘의 가정이 된다.

### 더 파볼 것
- [Feature scaling (Wikipedia)](https://en.wikipedia.org/wiki/Feature_scaling) — min-max 재척도와 z-score 표준화의 정의, 이상치에 약하다는 점과 중앙값·IQR을 쓰는 robust scaling. safe/redline 방식이 무엇을 피하려 한 것인지 대조해서 볼 수 있다.
