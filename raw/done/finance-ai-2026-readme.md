# 구독컷 · 해외 구독·클라우드 이상청구 대응 비서

카드 알림 문자, 청구 메일, 거래내역을 붙여넣으면 **지금 상황 → 24시간 안에 할 일(3단계) → 카드사에 낼 서류** 순서로 대응을 준비합니다. 발송과 접수는 사용자가 직접 결정합니다.

## 실행

```sh
npm ci
npm run dev
```

http://localhost:3000 에서 시작합니다. 첫 화면의 **예시 사건 3종**(해지 후 청구, 중복 승인, API 키 유출 의심)은 API 키 없이 동작하는 합성 사례이며 화면에 "예시" 도장으로 표시됩니다. 카드사는 예시마다 미리 지정돼 있습니다. `?case=claude`(duplicate / aws)로 특정 예시를 바로 열 수 있고, `&tab=todo`(questions / why / documents)를 붙이면 그 영역으로 스크롤됩니다. 결과 화면은 탭 없이 한 페이지로, 지금 상황 → 지금 할 일(3단계) → 확인 질문 → 왜 이렇게 판단했나(접힘) → 카드사에 낼 서류 순입니다.

실제 분석은 `.env.example`을 `.env.local`로 복사한 뒤 서버 환경변수 `OPENAI_API_KEY`를 설정하세요. `OPENAI_MODEL` 기본값은 `gpt-5.6-sol`입니다. 키를 화면이나 Git에 입력하지 마세요.

## 화면 흐름

1. **입력** – 카드 알림 문자·거래내역, 청구 메일·청구서, 상황 설명 세 슬롯에 있는 자료만 붙여넣습니다. 카드 문자·청구 화면 캡처는 사진(JPG·PNG·WEBP, 최대 4장)으로 첨부할 수 있고, 브라우저에서 1600px 이하 JPEG로 줄여 보냅니다. 서버는 먼저 사진 속 글자를 옮겨 적어(멀티모달 호출) 마스킹한 뒤 원문에 이어 붙이고, 이후 단계는 텍스트만 봅니다. 세 슬롯은 헤더를 붙여 하나의 문자열로 합쳐 전송하며, 전송 전 개인정보 마스킹 결과를 확인합니다. 사진은 자동 마스킹되지 않습니다.
2. **진단** – 이상 신호(급증, 중복, 해지 후 청구, 미승인 사용량, 승인 거절 반복 등), 가맹점 표기 해독(`STRIPE *`, `OPENAI`, `AMZN WEB SERVICES` 등 → 실제 서비스와 공식 창구), 발신 도메인 확인, 원문 인용 기반 사실, 확인 질문.
3. **24시간 계획** – 더 나가는 돈 막기(1시간) → 가맹점 환불 요청(12시간) → 카드사 접수 준비(24시간). 사건 유형과 결제 상태에 따라 고정 절차가 정해지고, AI 제안 행동이 긴급도별로 합쳐집니다. 거래일 기준 120일 참고 기한과 체크리스트 진행률을 표시합니다.
4. **이의신청 패키지** – Visa·Mastercard 사유코드 후보와 주의사항, 증빙 체크리스트와 준비도, 카드사 이의신청서 항목 미리 채우기, 영문 문의·국문 사실 정리·타임라인 초안, Markdown 내보내기.
5. **연결 보드** – 단서·사건·질문·행동·근거를 드래그 가능한 보드로 봅니다.

새 회신을 붙여넣으면 재분석하고 변경점을 표시합니다. 저장 버튼으로 사건과 체크 상태를 이 브라우저에 7일간 보관할 수 있습니다.

## 디자인

사건 접수증(승차권) 은유를 씁니다. 크림색 종이 위에 남색 잉크, 붉은 도장, 청록 레일. 제목은 Bodoni Moda, 본문은 Spectral, 라벨은 Space Mono이고 한글은 Noto Serif KR·Noto Sans KR로 글리프 단위 폴백합니다. 사건 티켓(제목·도장·상세 5칸) 아래로 지금 할 일(번호 단계), 확인 질문, 접힌 판단 근거, 서류 버튼이 한 페이지로 이어집니다. 참고: usehallmark.com custom-02.

## 근거 데이터와 인용

`data/` 아래에 카드사 9곳 이의신청 절차, Visa·Mastercard 사유코드 14개, 사업자 정책 18곳, 금감원·소비자원 안내, 카드 문자 패턴을 출처·조회일과 함께 두었습니다(자세한 내용은 `data/README.md`). 화면에서는 이렇게 쓰입니다.

- 사건 티켓의 카드사 선택 → 패키지의 접수 안내(채널·기한·서류·처리기간·사유 명칭), 계획의 카드사 단계, 신청서 항목
- 가맹점 표기 해독 → 환불 조건·해지 규칙·미승인 창구·처리 기간을 확인 수준 배지와 출처로 표시
- 분석 시 사건에 맞는 규정·정책 조각(`lib/references.ts`)을 둘째 LLM 호출에 주입하고, 판단 근거 최대 4개를 인용 칩으로 표시. 조각에 없는 코드·기한은 쓰지 못하게 제한
- 카드 문자 슬롯은 규칙 파서(`parseNotification`)가 먼저 읽어 표기·금액·승인 유형·카드사를 확정하고, LLM 추출 결과를 보정

## 규칙 엔진과 생성형 AI의 역할 분리

- `lib/playbook.ts` (LLM 없음): 가맹점 표기 사전, 사유코드 매핑, 증빙 체크리스트와 자동 체크, 24시간 플레이북, 120일 참고 기한, 이의신청서 항목.
- `lib/agent.ts` (OpenAI Responses API + Zod Structured Outputs): 비정형 입력에서 사실·신호 추출(원문 인용 검증), 사실과 안내 자료를 대조한 질문·행동·초안 생성. `store: false`, 입력 길이 제한, 취소 시 요청 중단.
- API 키 유출은 카드 도용 사유코드로 자동 매핑하지 않으며, 신청기한은 참고치로만 표시합니다.

## 검증

```sh
npm test
npm run typecheck
npm run build
```

테스트는 마스킹, 발신 도메인 오인 방지, 원문에 없는 증거 제거, 합성 사례 스키마, 가맹점 표기 해독, 사유코드 매핑, 참고 기한 계산, 플레이북 구성, 증빙 자동 체크, 신청서 항목을 확인합니다.

## 구성

- `app/page.tsx` – 상태와 흐름 (입력, 분석 스트림, 저장, 내보내기)
- `components/Landing.tsx` – 첫 화면과 예시 사건
- `components/Workspace.tsx` – 단계 내비게이션과 사건 요약
- `components/Diagnose.tsx`, `Plan.tsx`, `Package.tsx`, `Board.tsx` – 각 단계 화면
- `app/api/agent/route.ts` – 입력 제한, 마스킹, SSE 응답
- `lib/case.ts` – 스키마, 라벨, 마스킹, 원문 검증
- `lib/playbook.ts` – 규칙 엔진 (플레이북, 사유코드 후보, 증빙, 신청서)
- `lib/knowledge.ts`, `lib/references.ts` – 수집 데이터 로더, 문자 파서, 근거 조각 구성
- `data/` – 카드사·사유코드·사업자 정책·당국 안내·문자 패턴 (출처·조회일 포함)
- `lib/rules.ts` – 출처가 있는 일반 안내
- `lib/samples.ts` – 합성 예시 3종

제출 서류(기획서·기능명세서)의 원고는 `tools/submit/spec_plan.py`, `spec_spec.py`이고, 완성본은 `docs/submit/`에 hwpx·PDF로 있습니다. 다시 만드는 방법은 `tools/submit/README.md`에 있습니다.
