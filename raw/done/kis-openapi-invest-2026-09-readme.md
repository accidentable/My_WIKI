# MA5 돌파 역발상 봇 — 한투 OpenAPI 실전투자대회

5일 이동평균선 아래에 머물던 KOSPI100 종목이 09:05 시점에 5일선을 위로 넘으면
전액 매수하고, 익절·5일선 이탈·보유기간 중 먼저 닿는 조건에서 청산한다.

---

## 전략

### 진입 — 매일 09:05, 조건을 모두 만족하는 1종목

| # | 조건 | 왜 |
|---|------|-----|
| 1 | 직전 5거래일 중 3일 이상 종가가 그날의 5일선 아래 | "5일선 아래에서 놀던" 상태 확인 |
| 2 | 전일 종가 < 전일 5일선 | 어제까지도 눌려 있었다 |
| 3 | **현재가 > 직전 4거래일 종가 평균** | 지금 5일선을 위로 넘었다 |
| 4 | 전일 종가 대비 상승률 ≤ 5% | 이미 급등한 건 추격하지 않는다 |
| 5 | 전일 종가 > 60일선 | 하락추세에서 반등 실패를 거른다 |
| 6 | 20일 평균 거래대금 ≥ 30억 | 전액 주문을 소화할 유동성 |

조건 3이 5일선 돌파와 같은 말인 이유:

```
오늘 5일선 = (C₁+C₂+C₃+C₄+P)/5      C₁~C₄ = 직전 4거래일 종가, P = 현재가

P > (C₁+C₂+C₃+C₄+P)/5
  ⟺ 5P > C₁+C₂+C₃+C₄+P
  ⟺ 4P > C₁+C₂+C₃+C₄
  ⟺ P > (C₁+C₂+C₃+C₄)/4
```

장중에는 오늘 종가가 없어서 5일선이 확정되지 않는다. 위 변형 덕분에
**직전 4일 종가 평균 하나만 있으면** 현재가로 즉시 판정할 수 있다.
청산 조건인 5일선 이탈도 부등호만 뒤집으면 된다.

### 종목 선정 — 후보가 여럿이면 점수 1위 하나만

| 지표 | 의미 | 가중치 |
|---|---|---|
| depth | 전일 이격도가 낮을수록 ↑ (깊이 눌렸다 올라옴) | 1.0 |
| thrust | 돌파 강도 | 0.5 |
| trend | 60일 이격도 | 0.5 |
| value | 20일 평균 거래대금 | 0.3 |

각 지표를 후보 집단 내 백분위로 환산한 뒤 가중합한다. 절대값이 아니라 상대순위라
지표 간 단위 차이에 영향받지 않는다.

### 청산 — 먼저 닿는 것

| 조건 | 판정 시점 |
|---|---|
| +10% 익절 | 장중 감시 (10분 간격) |
| 5일선 이탈 | 장중 감시 |
| 3거래일 경과 | 마감 정리(15:15)에만 |

- **손절선은 없다.** 5일선 이탈이 유일한 방어선이다. 갭하락은 그대로 맞는다.
  넣으려면 `.env` 에 `USE_STOP_LOSS=true`, `STOP_LOSS_PCT=3` 을 추가하면 된다.
- 5일선 기준가는 매일 아침 갱신된다. 진입 당시 값을 고정해두면 청산 판정이 틀어진다.
- 보유일차는 진입일이 1일차다. `MAX_HOLD_TRADING_DAYS=3` 이면 3일차 장 마감에 정리된다.

### 포지션

**1종목 × 100%.** 분산이 없으므로 한 종목의 악재가 곧 계좌 전체다.
`MAX_POSITIONS` / `POSITION_PCT` 로 조정할 수 있다.

매수 수량은 한투의 **미수없는매수수량**을 기준으로 잡는다. 미수(증거금 대출)를
쓰면 반대매매 위험이 생기고 대회 수익률 계산이 꼬인다.

## 구조

```
config.py              환경변수 + 전략 파라미터 (전략 튜닝은 여기서)
core/
  kis/
    auth.py            토큰 발급·캐싱 (파일 또는 SSM)
    client.py          호출 래퍼 — 유량제한, 재시도, 토큰 만료 자동 복구
    quotes.py          현재가 / 일봉 / 휴장일
    trading.py         주문·취소·잔고·미체결·체결내역
    tick.py            호가단위 보정
  universe.py          KOSPI100 (한투 종목마스터 파싱)
  strategy.py          돌파 판정 + 점수화
  state.py             포지션·이력 저장 (JSON 또는 DynamoDB)
  trader.py            주문 실행 + 청산 판단
  notify.py            텔레그램 발송
  commands.py          텔레그램 명령 처리
jobs/
  scan.py              시그널 스캔
  entry.py             09:05 진입
  monitor.py           장중 청산 감시
  close.py             15:15 마감 정리 + 리포트
handlers/aws.py        람다 진입점 4개
infra/deploy.py        AWS 배포
cli.py                 로컬 실행
tests/test_pipeline.py API 없이 도는 통합 점검
```

### 유니버스를 마스터파일에서 뽑는 이유

한투가 공개하는 `kospi_code.mst` 에 **KOSPI100 편입 플래그**가 그대로 들어있다.
관리종목·거래정지·정리매매·시장경고·단기과열·공매도과열·우선주 플래그도 같은 파일에 있어서,
지수 구성종목을 스크래핑하거나 FinanceDataReader 같은 외부 라이브러리를 쓸 필요가 없다.

파싱은 고정폭 문자열 슬라이싱이라 pandas도 필요 없다. **런타임 의존성은 `requests` 하나**이고,
그래서 람다 배포 패키지가 몇 MB에 그친다.

## 시작하기

### 1. 설치

```bash
pip install -r requirements.txt
```

```bash
cp .env.example .env
```

`.env` 에 한투 실전 APP_KEY / APP_SECRET / 계좌번호 10자리와 텔레그램 토큰을 채운다.
**`DRY_RUN=true` 는 그대로 둔다.**

### 2. 연결 점검

```bash
python cli.py check
```

토큰 발급 → 시세 조회 → 잔고 조회 → 휴장일 조회까지 한 번에 확인한다.

### 3. 로직 점검 (API 키 없이도 됨)

```bash
python tests/test_pipeline.py
```

### 4. 장중에 스캔만 돌려보기 (주문 없음)

```bash
python cli.py scan
```

### 5. 하루 흐름 수동 실행

```bash
python cli.py entry --force
```

```bash
python cli.py monitor --force
```

```bash
python cli.py close --force
```

`--force` 는 휴장일 체크를 건너뛴다. `DRY_RUN=true` 인 동안에는 주문이 전송되지 않고
로그와 텔레그램 알림만 나간다.

### 6. 실매매 전환

`.env` 에서 `DRY_RUN=false`. 되돌릴 때는 다시 `true`.

## 운영 방식

### A. 서버 1대 상주 — 권장 (네이버 클라우드 Micro Server 등)

```bash
python cli.py serve
```

이 한 줄이 전부다. APScheduler 가 09:05 진입 / 장중 10분 감시 / 15:15 마감을 KST 로 돌리고,
같은 프로세스 안에서 텔레그램 **롱폴링** 스레드가 명령을 받는다.

롱폴링이라 **공개 엔드포인트도, 인바운드 포트도 필요 없다.** 서버가 텔레그램 쪽으로
나가는 연결만 쓴다. 웹훅을 안 쓰니 `getUpdates` 409 충돌도 구조적으로 생기지 않는다.

상태는 `data/state.json`, 토큰은 `data/kis_token.json` 에 저장된다
(`STATE_BACKEND=local`, `TOKEN_CACHE=file`).

서버 초기 설정은 스크립트 하나로 끝난다:

```bash
bash infra/ncp/setup.sh
```

시간대 KST 설정 → 파이썬/venv → 의존성 → `cli.py check` 점검 → systemd 등록까지 한다.
`Restart=always` 라 프로세스가 죽어도 10초 뒤 자동으로 다시 뜬다.

```bash
sudo systemctl status ma5-bot
```

```bash
tail -f /opt/ma5-bot/bot.log
```

### B. AWS 람다 (대안)

```bash
python infra/deploy.py all
```

DynamoDB + IAM 역할 → 람다 4개 → EventBridge 스케줄 → API Gateway + 텔레그램 웹훅.
부분 실행도 된다 (`bootstrap` / `lambdas` / `schedules` / `webhook`).

람다는 컨테이너가 매번 새로 뜨므로 상태를 DynamoDB, 토큰을 SSM 에 둬야 한다
(`deploy.py` 가 환경변수를 그렇게 넣는다). 서버가 죽을 걱정이 없는 대신,
컴포넌트가 5개로 늘고 장애 시 CloudWatch 를 뒤져야 한다.

### 옛 AWS 스택 정리

```bash
python infra/aws_cleanup.py --region ap-southeast-2 --prefix stock-bot
```

기본은 **조회만** 한다. 무엇이 남아 있는지 보고 나서 `--yes` 를 붙이면 삭제한다.

## 텔레그램 명령

| 명령 | 설명 |
|---|---|
| `/status` | 보유 포지션 + 손익 + 보유일차 + 현재 5일선 |
| `/scan` | 지금 기준 시그널 스캔 (주문 안 함) |
| `/history` | 최근 매매 이력 + 승패 |
| `/config` | 현재 설정 확인 |
| `/pause` | 자동 진입 정지 (보유 종목 청산 감시는 계속) |
| `/resume` | 재개 |
| `/sell 005930` | 강제 청산 |

LLM은 쓰지 않는다. 매매 판단은 전부 코드가 하고, 텔레그램은 모니터링과 비상 개입용이다.

봇 토큰은 `@BotFather` 에게 `/newbot`. chat ID 는 봇에게 아무 메시지나 보낸 뒤:

```bash
python cli.py chatid
```

예전 배포에서 남은 웹훅이 걸려 있으면 `getUpdates` 가 막힌다(409).
`--reset-webhook` 을 붙이면 해제하고 조회한다. `cli.py serve` 도 시작할 때 자동으로 해제한다.

## 한투 API 주의점

2025년 이후 규격이 바뀌어서 예전 코드는 그대로 쓰면 주문이 거부된다.

| 기능 | 구버전 | 현재 |
|---|---|---|
| 매수 | `TTTC0802U` | **`TTTC0012U`** |
| 매도 | `TTTC0801U` | **`TTTC0011U`** |
| 정정/취소 | `TTTC0803U` | **`TTTC0013U`** |
| 미체결 조회 | `TTTC8036R` | **`TTTC0084R`** |

- 주문 body 에 **`EXCG_ID_DVSN_CD`** 가 필수로 추가됐다 (NXT 대체거래소 출범).
  `KRX` / `NXT` / `SOR`(최선주문집행) 중 선택하며 기본값은 `KRX`.
- **호가단위**가 2023-01-25 개편으로 코스피·코스닥 통일됐다. 지정가가 호가에 안 맞으면
  주문이 거부되므로 `core/kis/tick.py` 를 반드시 통과시킨다.

  | 가격 | 호가단위 | | 가격 | 호가단위 |
  |---|---|---|---|---|
  | ~2,000 | 1 | | 50,000~200,000 | 100 |
  | 2,000~5,000 | 5 | | 200,000~500,000 | 500 |
  | 5,000~20,000 | 10 | | 500,000~ | 1,000 |
  | 20,000~50,000 | 50 | | | |

- 토큰은 24시간 유효하고 **재발급은 1분에 1회로 제한**된다. 여러 람다가 각자 발급하면
  제한에 걸리므로 SSM 으로 캐시를 공유한다.
- 유량제한은 실전 계좌 기준 초당 20건(조회), 주문은 초당 1건.
  `KIS_RATE_LIMIT_PER_SEC` 기본값은 8로 여유를 뒀다.

## 알아둘 것

- **09:05 판정은 5분치 데이터만 보고 내린다.** 오전에 5일선을 넘었다가 종가에 다시
  깨지는 속임수(whipsaw)가 구조적으로 존재한다. 이를 줄이려면 판정을 장 후반으로
  미뤄야 하는데, 그러면 당일 상승분을 놓친다. 지금은 즉시성을 택한 설정이다.
- **백테스트는 돌리지 않았다.** `+10%` `3거래일` `5일 중 3일` 같은 숫자는 합의된 규칙이지
  검증된 최적값이 아니다. 전부 `config.py` 와 `.env` 로 조정 가능하게 열어뒀다.
- 코스피100 대형주가 3거래일 안에 +10% 가는 일은 드물다. 실제 청산은 대부분
  5일선 이탈이나 기간 만료로 끝날 가능성이 높다.
