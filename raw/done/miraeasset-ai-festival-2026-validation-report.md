## 1. 왜 방법을 바꿨나

1·2차 검증은 질의를 우리가 만들었다. 그 구조에서는 과적합이 세 경로로 들어온다.

| 경로 | 내용 |
|---|---|
| 인스턴스 선택 | 템플릿은 주최 측 것이어도 `OO` 슬롯에 넣을 기업을 우리가 골랐다. 통과하는 사례만 고르게 된다 |
| 정답 결정 | 우리가 정답을 정하면 우리 출력을 정답으로 승인한다 |
| 검사 항목 선택 | 우리가 아는 실패 모드만 검사하니 새 실패 모드는 구조적으로 안 보인다 |

결정적으로, 과제소개자료 p7의 **"참고용 질의 set" 6종**과 대조해 보니
1·2차 세트 14문항은 **그 6개 템플릿에 기업 하나씩 끼운 것**이었다.
과적합이 숨는 자리가 정확히 그 슬롯이다.

이 진단은 추측이 아니다. README 9-1에 적은 골든셋 과적합(⑥번 결함)과
같은 원인이 이번에도 실제 오답으로 재현됐다(3절 참조).

## 2. 우회 설계

| | 1·2차 | 3차 |
|---|---|---|
| 질의 인스턴스 | 저자가 선택 | **DB(SQL)가 선택**, 결과 있음/없음 양쪽 강제 |
| 정답 | 저자가 판정 | **DB 직접 SQL** — `src/agent/tools.py` 미호출 |
| 오라클 없는 검사 | 없음 | 자기일관성 + 메타모픽 |
| 할루시네이션 | 육안 | 기계 판정 |

**L1 — 질의 인스턴스를 DB가 고른다.**
템플릿은 과제소개자료 참고 질의 6종 원문을 그대로 쓰고 슬롯만 SQL로 채운다.
`terminations`, `major_events` 등에서 **결과가 있는 기업과 없는 기업을
양쪽 다 강제로** 뽑는다.

**L2 — 정답을 도구가 아니라 독립 SQL로 만든다.**
`financial_facts` / `terminations` / `major_events` 에 직접 질의한다.
에이전트가 쓰는 도구를 부르지 않으므로 도구 버그가 오라클과 함께 틀리지 않는다.

**L3 — 정답이 없어도 판정되는 검사.**
- *자기일관성*: 비교 답변이 선언한 승자가 **자기가 쓴 두 숫자의 대소**와 맞는가,
  차액을 말하면 **뺄셈이 맞는가**. (2차의 0.93조 오차를 잡았던 바로 그 검사)
- *메타모픽*: 같은 사실을 다르게 물으면 같은 답이 나오는가.
  패러프레이즈 4종, 기업명 별칭 3쌍(현대차/현대자동차, 하이닉스/SK하이닉스,
  KT/케이티), 요청 프리픽스 부착.

**L4 — 할루시네이션 기계 판정.**
답변의 14자리 접수번호와 금액이 `retrieved_context` 안에 실재하는가.

**절차 규율** — 채점 기준을 먼저 코드로 고정하고 실행했다. 결과를 보고
기준을 고치지 않았다(단, 3-3의 체커 버그는 예외로 수정했고 그 사실을 남긴다).

## 3. 발견한 결함

### 3-1. 해지 질의가 골든셋 문구에 과적합 (심각)

`deterministic_termination` 은 **따옴표로 감싼 계약명**이 있어야 발동한다.

```python
r"^(.+?)(?:의|이|가)(?:\s+공시한)?\s+'([^']+)'\s+계약"
```

주최 측 템플릿 *"OO기업이 2025년에 체결한 주요 계약 이후 해지된 계약이
존재하는가?"* 에는 계약명이 없다. 따라서 이 유형은 **전부 모델 경로로** 빠졌다.

그동안 우리는 **해지가 없는 기업(HD현대중공업) 하나만** 검증했다. "없음"은
기본값이라 쉬운 쪽만 맞고 있었던 것이다. DB가 고른 **해지 실재 5개사**로
돌리자:

| 실행 | 실패 |
|---|---|
| 1회차 | 두산퓨얼셀(90.1초), 효성중공업(오답 "해지 없음") |
| 2회차 | 두산퓨얼셀(82.1초), 삼성E&A(오답 "해지 없음") |

**매 실행 5사 중 2사 오답, 실패 기업은 매번 달랐다**(모델 비결정성).
두산퓨얼셀은 두 번 다 `ANSWER_BUDGET_SECONDS`(90초) 한계까지 갔다 —
평가 하네스 타임아웃 위험.

**수정**: `deterministic_termination_scan` 신설
(`src/agent/orchestrator.py`). 존재 여부는 구조화 행으로 확정할 수 있다.

| | 수정 전 | 수정 후 |
|---|---|---|
| positive 5사 | 3/5 (변동) | **5/5** |
| negative 5사 | 5/5 | **5/5** |
| 응답 시간 | 10~90초 | **0.0~0.1초** |

계약명을 지정한 질의는 기존 경로가 그대로 맡는다(회귀 테스트로 고정).

### 3-2. `'예상되는 매출액'` 활용형 누수

`validated_disclosed_facts` 는 `'예상 매출액'` 은 막았지만 `'예상되는 매출액'`
은 통과시켰다(`되는` 때문에 lookahead 불일치). DB가 고른 무작위 24개사 매출
스윕에서 **세아베스틸지주 1건**이 샜다. 값(3,651,585,276,954원)과 접수번호는
정확했고 수식어만 남았다.

**수정**: `되는 / 된 / 되었던 / 되어 있는 / 하는 / 치` 활용형까지 제거.

### 3-3. 체커가 틀린 것 4가지 — 시스템 결함으로 오해할 뻔했다

G4(설비투자 비교)가 처음엔 대량 실패로 나왔다. **12건을 전부 손으로 검산하니
모두 정확했다.** 원인은 내 체커였다.

| 오탐 | 실제 |
|---|---|
| "차액 오차: 20,260,310,002,820" | 금액이 아니라 **접수번호** `20260310002820` (14자리라 금액 정규식에 걸림) |
| "근거에 없는 수치 44,455,328,073,257" | 47,522,179,000,000 − 3,066,850,926,743 = **정확한 차액**. 계산값은 근거에 있을 수 없다 |
| "선언한 승자가 불일치" | 승자 추출 창(70자)이 상대 기업 숫자를 집음 |
| "순서 대칭 실패" | 문장 첫머리 기업명을 승자로 오인 |

**교훈: 자동 검사도 저자가 쓰면 틀린다.** 체커를 고쳐 저장된 응답에
재적용하니 오탐이 전부 사라졌고, 수기 검산과 일치했다.

검산 확인 (전부 정확):

```
삼성전자 47,522,179,000,000 − 삼성SDI  3,066,850,926,743 = 44,455,328,073,257
삼성전자 47,522,179,000,000 − 현대차   8,366,764,000,000 = 39,155,415,000,000
SK하이닉스 27,518,924,000,000 − LG엔솔 10,833,917,000,000 = 16,685,007,000,000 (154.01%)
삼성전자 / HMM = 29.8211배 → 2882.11% 큼
```

## 5. 남은 한계

- **3차 방법론도 결국 우리가 설계하고 실행한다.** 독립 SQL 오라클 역시 우리가
  스키마를 읽고 작성했으므로 파싱 단계의 오해까지는 함께 틀릴 수 있다.
- L5는 **최종 답변** 기준이라 모델 원문 전체를 덮지 못한다. 서버가 필터 적용
  전 원문을 남기지 않기 때문이다.
- G4의 절대 정답(설비투자 금액)은 오라클이 없다. 자기일관성과 순서 대칭만
  봤다. 절대값은 기존 단위 테스트 4건이 고정한다.
- 진짜 독립을 원하면 **구현을 보지 않은 별도 에이전트에게 질의를 쓰게 하는
  것**이 남은 카드다.
